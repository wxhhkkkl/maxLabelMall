# 数据模型（003）

Phase 1 产出。三个新实体、两张既有表的映射，以及由它们派生的查询口径。

> **命名沿用 yudao 既有约定**：表名 `product_*`、逻辑删除 `deleted`、多租户 `tenant_id`、
> 审计 `creator / updater / create_time / update_time`，全部由 `BaseDO` 自动填充 ——
> 新表 MUST 继承 `BaseDO`，MUST NOT 自行加这些列的定义。

---

## 1. 实体

### 1.1 筛选维度 `product_filter_dimension`（**新增**）

挂在某个商品分类下的一组筛选条件，例如「碳带」下的「宽度」。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `category_id` | bigint | 归属分类。**单一归属**，继承靠祖先链实时求（R4） |
| `name` | varchar(32) | 维度名，如「宽度」 |
| `sort` | int | 展示顺序（前台按它排，MUST NOT 按任何运行时数据重排 —— FR-112） |
| `remark` | varchar(255) | 备注，运营可用 |
| `<BaseDO 列>` | | `creator/updater/create_time/update_time/deleted/tenant_id` |

**校验规则**

- `name` 非空，去空白后长度 1~32。
- **同一条分类祖先链上不允许同名**（FR-091）：创建/更新时，取 `{category_id} ∪ ancestors(category_id)`
  上已有的全部维度，若其中存在重名的（**排除自身**）→ 拒绝，错误信息指明"与分类「碳带」下的
  「宽度」重名"。⚠️ **不是只查同一 `category_id`** —— 那是 Q10=A 的口径，会漏掉父子重名。
- `category_id` 必须指向一个**存在且启用**的分类。

### 1.2 维度可选值 `product_filter_value`（**新增**）

属于某个维度，例如「宽度」下的「110」。**前台可点的就是它。**

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `dimension_id` | bigint | 所属维度 |
| `name` | varchar(32) | 值名，如「110」「1英寸（25.4毫米）」 |
| `sort` | int | 展示顺序（FR-112） |
| `remark` | varchar(255) | |
| `<BaseDO 列>` | | |

**校验规则**

- `name` 非空，去空白后长度 1~32。
- **同一维度下不允许同名值**（排除自身）。
- `dimension_id` 必须指向一个存在的维度。

**删除规则（FR-092）**

删除维度 → **级联**删除它的全部可选值；删除可选值 → 删除它身上的全部商品关联。
两处都 MUST 先返回**被引用的商品数**供后台确认，MUST NOT 留下指向已删除项的关联。

### 1.3 商品 × 可选值关联 `product_spu_filter_value`（**新增**）

**多对多**，前台筛选的**唯一依据**（FR-094）。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `spu_id` | bigint | `product_spu.id` |
| `filter_value_id` | bigint | `product_filter_value.id` |
| `<BaseDO 列>` | | |

**索引**：`(spu_id)`、`(filter_value_id)`、**`(spu_id, filter_value_id)` 唯一**。
`filter_value_id` 上的索引服务筛选时"按值找商品"这一方向（R5 的 `EXISTS` 子查询）。

**校验规则（写入商品时）**

- 允许**同一维度内挂多个值**，也允许跨维度各挂若干（FR-094）。
- **辖域校验（FR-095）**：值所属维度的 `category_id` MUST ∈ `{商品分类} ∪ ancestors(商品分类)`。
  不满足的**不进关联**。
- **改分类时的剔除（FR-097 / R11）**：保存商品时，把此前挂上、但已**不在新分类祖先链**上的关联
  一并删除，并向后台返回"已移除 N 个不再适用的筛选标签"。

## 2. 与既有表的映射

| 新实体 | 关联的既有表 | 关系 |
|---|---|---|
| `product_filter_dimension.category_id` | `product_category.id` | 多对一（多个维度挂同一分类） |
| `product_spu_filter_value.spu_id` | `product_spu.id` | 多对多 |
| 商品所属分类 | `product_spu.category_id` | 决定该商品能挂哪些值（FR-095） |

**不改动任何既有表**。`product_property` / `product_property_value` / `product_sku.properties`
**一律不碰**（R1 已否决复用；它们服务的是 SKU 规格，与筛选无关）。

## 3. 派生数据

### 3.1 分类祖先链（R4）

```
ancestors(categoryId) = 沿 product_category.parent_id 向上走到根的全部 id（不含自身）
scopeOf(categoryId)   = {categoryId} ∪ ancestors(categoryId)
```

分类树 **3 层、42 个分类**（线上实测）。实现：一次性加载启用分类（42 行），在内存里走链，
带一个**深度上限**（比如 10）防止数据异常时死循环。

**两个用途，方向相反，别搞混**：

| 用途 | 用什么 | 含义 |
|---|---|---|
| 前台**显示**哪些维度（FR-098） | `dimension.category_id ∈ scopeOf(浏览的分类)` | 维度的归属分类在**浏览位置的祖先链上** |
| 商品**可挂**哪些值（FR-095） | `dimension.category_id ∈ scopeOf(商品的分类)` | 维度的归属分类在**商品分类的祖先链上** |

两者是同一个函数、同一条规则，只是代入的分类不同 —— 这正是 Q10=B「向下继承」的全部内容。

### 3.2 筛选条件（前台状态 → 查询参数）

| 规格里的概念 | 查询参数 | 语义 |
|---|---|---|
| 当前分类 | `categoryId`（既有） | 后端**已经**会展开成该分类及其子分类（`ProductSpuServiceImpl` 既有行为，不改） |
| 关键词 | `keyword`（既有） | 只匹配商品名（既有） |
| 排序 | `sortField` / `sortAsc`（既有） | 既有白名单不变 |
| **已选的维度值** | **`filterValueIds`（新增，可选）** | 值 id 的**扁平数组**；**每个维度至多一个**（Q9=B 单选），服务端为每个值追加一条**等值** `EXISTS`，跨维度 AND。同维度传入多个 = 非法请求（R9） |

### 3.3 选项集合（FR-111）—— **没有计数**

**服务端不聚合商品数**（Q11=A / R6）。筛选条上的选项集合就是：

```
options(categoryId) = 全部 dimension where dimension.category_id ∈ scopeOf(categoryId)
                      的 values，按各自 sort 排
```

**三条性质**：

1. **静态**：与关键词、已选值、实际商品数**完全无关**。同一个分类页上，选项集合不会变。
2. **维度无值 → 整行不出现**（FR-090）——这是整行不渲染的**唯一**情形，
   与"这个值有没有商品"无关。
3. **顺序 = 运营设定**（`dimension.sort` / `value.sort`，FR-112），
   前端 MUST 按 `sort` 自行排序，不得依赖接口返回的数组顺序。

**空结果怎么办**：某个值当前没有商品，选项**照常展示**，点选后走空态（FR-105）。
空态下**筛选条整块保留**（FR-113）—— 顾客必须能取消条件。

## 4. 展示状态

### 4.1 筛选条（前台）

| 状态 | 触发条件 | 表现 |
|---|---|---|
| **不渲染** | 分类本身及其全部祖先都没有配置维度；或配了的维度全都**没有可选值** | 整块不出现，**不留空白块**（FR-104） |
| **某行不渲染** | 该维度下**没有可选值**（FR-090） | 其余行照常，**不得**留下空白行或错位 |
| **渲染** | 至少一个维度有可选值 | 每维度一行，行首「全部」，其后按 `sort` 排 |
| **某项选中** | 该项在当前已选集合里 | 高亮；再点取消 |
| **某项当前无商品** | 该值当前筛不出商品 | **照常渲染、照常可点**（Q11=A）—— 选项集合与商品数无关 |
| **一行放不下值**（窄屏或值多） | 值区宽度超出 | **横向滚动**该行，「全部」固定在行首、不随滚动移出；**不折行**（Q13） |

### 4.2 空结果（前台）

商品列表为 0 时：**筛选条整块照常保留**（含已选中的值，顾客要能取消条件）
+ 商品区显示空态，明说"当前条件下没有商品"。
**MUST NOT** 把筛选条一起收掉 —— 那会把顾客困在自己造出来的空结果里。
**MUST NOT** 另设「清除筛选」按钮（Q12 / FR-114）—— 取消条件靠行首的「全部」逐个来，
清关键词靠搜索框自带的清空按钮。

### 4.3 后台

| 位置 | 状态 |
|---|---|
| 商品分类页 → 「筛选维度」抽屉 | **本分类自有**（可增删改排序）+ **继承自父分类**（只读，标注"继承自「碳带」"—— FR-110） |
| 商品编辑页 → 筛选标签子表单 | 按 `scopeOf(商品分类)` 列出可选值，按维度分组多选；**分类变更后保存时可能被剔除一部分**，保存成功的提示里要说明（R11） |

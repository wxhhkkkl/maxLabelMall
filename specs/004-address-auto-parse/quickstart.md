# 手工验证清单：收货地址自动解析

> 自动化测试（`address-parse.spec.ts` + `AddressFormDialog.spec.ts`）覆盖逻辑与交互。
> 本清单用于**人眼确认**那些单测断言不了的东西：文案是否说人话、下拉是否真的选中了、
> 视觉上有没有跳变。**不要用本清单替代单测。**

## 前置

```bash
cd storefront && pnpm dev
```
用任一已登录的会员账号进 `/account/address` → 点「新增收货地址」。
（结算页 `/checkout` 里的同一个弹层也应表现一致 —— 它是同一个组件，抽出来就是为了两处共用。）

## 一、主路径（US1 / FR-116~119 / Q15=A、Q17=A）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 在「粘贴整段地址」框里粘 `浙江省杭州市余杭区文一西路969号`，点「自动识别」 | 省=`浙江省`、市=`杭州市`、区=`余杭区` 三个下拉**被选中**；详细地址=`文一西路969号` |
| 2 | 直接点「保存」 | 保存成功，落库的地区编号是 `330110`（余杭区） |
| 3 | 同上但粘 `浙江杭州余杭区文一西路969号`（无后缀） | 与 #1 完全相同的结果（FR-122） |
| 4 | 粘 `北京市朝阳区建国路88号` | 省=`北京市`、市=`北京市`、区=`朝阳区`；详细地址=`建国路88号` |

## 二、失败与半失败（US2 / FR-120、121 / Q16=A）

| # | 操作 | 期望 |
|---|---|---|
| 5 | **先手动**选好「广东省 / 深圳市 / 南山区」，再粘 `某某小区3号楼2单元501` 点识别 | 三级选择**原样不动**；给出"未识别到行政区划"的提示；详细地址**也没被改**（FR-121） |
| 6 | 粘 `浙江省杭州市` 点识别 | 省、市被填上；**区保持原来的值**（原为空就仍为空）；提示区县未识别到（FR-120 / Q16=A） |
| 7 | 在 #6 之后点「撤销识别」 | 省/市回到识别前，**区回到识别前的值**（FR-123） |
| 8 | 断网刷新后打开弹层（制造地区树加载失败） | 识别按钮**禁用**并说明原因；三级下拉本来就是空的（US2 场景 3） |
| 9 | 「粘贴整段地址」框留空直接点识别 | **必须给出**明确提示（文案区分于"认不出来"：如「请先粘贴地址」）；**不得**清空表单的任何字段（FR-121） |

## 三、覆盖语义与撤销（Q16=A / US3）

| # | 操作 | 期望 |
|---|---|---|
| 10 | 手动选好「广东省 / 深圳市」，再粘 `浙江省杭州市余杭区…` 点识别 | 省市区被**覆盖**为浙江 / 杭州 / 余杭（Q16=A） |
| 11 | 接着点「撤销识别」 | 回到 #10 之前的「广东省 / 深圳市」 |
| 12 | 连续做两次识别（第二次粘别的省），再点撤销 | 只回到**最近一次**识别前，不是两次都退（US3 场景 2） |
| 13 | 在识别前手打完收件人「李四」与手机号，再粘带「张三 18748935785」的整段地址识别，然后点撤销 | 识别时收件人/手机号被覆盖为张三/18748935785；撤销后**回到李四与原来手打的手机号**（Q55 后这两个字段也进快照） |
| 13a | 粘 `张三 18748935785 浙江省杭州市余杭区文一西路969号` | 收件人=张三、手机号=18748935785，详细地址=`文一西路969号`（姓名与号码不再残留） |
| 13b | 粘 `张三 18748935785 某某小区3栋`（无行政区划） | 收件人/手机号照填，省市区与详细地址**一个都不动**，提示未识别到行政区划（Q56） |

## 四、不得回归（FR-127）

| # | 操作 | 期望 |
|---|---|---|
| 14 | 什么都不识别，像以前一样手动选三级下拉 + 手打详细地址 + 保存 | 行为与改动前**一字不差**，保存成功 |
| 15 | 打开**编辑**已有地址 | 三级下拉与详细地址按原值回显，识别入口可用且不影响回显 |

## 五、SC-042 的人眼对照子集（与自动化断言互为对照）

> `storefront/src/utils/address-parse.spec.ts` 的表驱动用例里；本表这 7 条 MUST 是那份用例集的子集，
> 两边断言 MUST 一致。

| 样本文本 | 期望省 / 市 / 区 | 期望详细地址 |
|---|---|---|

| `浙江杭州余杭区文一西路969号` | 浙江 / 杭州 / 余杭区 | `文一西路969号` |

| `杭州市余杭区文一西路969号` | 浙江省（补出）/ 杭州市 / 余杭区 | `文一西路969号` |
| `浙江省杭州市` | 浙江省 / 杭州市 / —（进 missing） | 空（**不回填**） |
| `某某小区3号楼2单元501` | — / — / —（全部 missing） | 空，且**一个字段都不改** |
| `从浙江发到广东，收货在杭州` | 浙江省（取最靠前的）/ — / — | 原文剩余部分（**注意**：这条会带出不太好看的剩余文本，属预期） |

## 六、明确不验证（显式声明，不假装验过）

| 不验证的事 | 理由 |
|---|---|
| e2e（Playwright） | 本期不加。识别是纯前端交互，组件层已完整覆盖；再加一条只会得到一个更慢更脆的重复断言（见 plan.md 测试策略） |
| 小程序 / App 端（`yudao-ui-mall-uniapp`） | **不在本期范围**，沿用 003 已确立的先例 |
| 真机 / 移动端浏览器 | 是纯逻辑 + 原生 `<select>` 的改动，不涉及新的响应式布局 |
| 真实用户地址语料的大规模准确率 | SC-042 的"≥90%"用**固定样本集**度量，不做线上语料抽样统计 |
| 性能压测 | SC-045 只要求"感知为即时"；纯内存匹配约 3.6k 节点，人力点一次即可判断，不做基准测试 |
| 姓名 / 手机号识别的**准确率统计** | 只做保守规则内的样本断言（Q55），不做线上语料抽样；样本外的写法一律留空 |

# C 端接口契约（010 订单物流跟踪）

> 前缀：**只走 `/app-api`**（宪法约束）。需要登录态（`Authorization: Bearer …`）。
> 所有 `LocalDateTime` 字段由 yudao 全局序列化为 **epoch 毫秒数**（数字），不是字符串。

---

## 1. `GET /trade/order/get-express-track-list` —— 物流轨迹（**沿用既有接口**）

```
GET /app-api/trade/order/get-express-track-list?id=900
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 交易订单编号（**不是支付单号**） |

```jsonc
// 成功：有轨迹
{ "code": 0,
  "data": [
    { "time": 1729732800000, "content": "【上海市】快件已签收，签收人：…" },
    { "time": 1729729200000, "content": "【上海市】快件已到达…" }
  ],
  "msg": "" }

// 成功：未发货 / 没有运单号 —— **不是错误**，返回空数组
{ "code": 0, "data": [], "msg": "" }
```

| 规则 | 说明 |
|---|---|
| 顺序 | **按 `time` 倒序**（最新在最上面），由服务端保证 |
| 归属校验 | 只允许查**自己的**订单；非本人订单一律返回 `ORDER_NOT_FOUND`（不泄露订单是否存在） |
| 未发货 | `[]`。前端据此不渲染物流区块（FR-254） |
| 空轨迹 | `[]`。前端在"有运单号"的前提下据此显示「暂无轨迹信息」（FR-260） |
| 编码缺失 | 返回 **`1_011_004_103`**，前端显示「该快递公司暂不支持查询」（FR-261） |
| 第三方失败 | 返回 `1_011_004_101` / `102`，**文案不含第三方原文**；详情由服务端日志承载（FR-259 / FR-274） |

**错误码**：

| code | 含义 | 前端表现 |
|---|---|---|
| `1_011_000_011` | 交易订单不存在 / 不属于当前客户 | 按订单详情整体的错误处理，不单独提示 |
| `1_011_004_000` | 快递公司不存在（数据被删） | 统一降级提示 |
| `1_011_004_101` | 快递查询接口异常（网络 / 非 2xx） | 统一降级提示 |
| `1_011_004_102` | 快递查询返回失败（含限频 / 编码错误 / 凭据问题） | 统一降级提示 |
| `1_011_004_103` | **该快递公司暂不支持物流查询**（新增） | 「暂不支持查询」 |

## 2. `GET /trade/order/page` —— 列表项加 `logisticsNo`

```jsonc
{ "code": 0, "data": {
  "list": [
    { "id": 900, "no": "…", "status": 20,
      "logisticsNo": "SF1234567890",   // ← 新增；未发货 / 虚拟 / 自提为 null
      "items": [ … ] }
  ], "total": 1 } }
```

**为什么要加**：C 端「我的订单」要在**确实有运单号**时才显示「查看物流」入口（FR-273 / Q59）。

- 不能用 `status >= 20` 代替：历史导入单里存在"已完成但没有运单号"的订单，
  按状态给入口会把人送到一个没有物流区块的详情页。
- 字段缺失 / `null` / 空串 → 不显示入口。

## 3. `GET /trade/order/get-detail` —— **无需改动**（确认既有字段）

物流抬头所需字段**后端已返回**，本特性只消费、不改契约：

```jsonc
{ "code": 0, "data": {
  "deliveryType": 1,
  "logisticsName": "顺丰速运",       // 已存在
  "logisticsNo": "SF1234567890",    // 已存在
  "deliveryTime": 1729720000000,    // 已存在；epoch 毫秒
  "receiverMobile": "138****", … } }
```

前端落点（`storefront/src/views/OrderDetailView.vue`）：

1. 订单详情加载完成后，若 `logisticsNo` 非空 → **自动**请求 §1 的轨迹（Q58）；
2. 物流卡插在**收货信息之后、买家留言之前**；
3. 失败不阻塞页面其余内容（FR-258）；不展示第三方错误原文（FR-259）。

---

## 4. 明确不改的接口

| 接口 | 结论 |
|---|---|
| `GET /trade/order/get-detail` | 字段已足够，**不加字段** |
| 小程序 / App 的物流页（`/trade/order/get-express-track-list`） | 同一接口，**响应结构不变**，回归即可 |

## 5. `GET /trade/order/get-express-map-url` —— 物流地图（010 追加）

```
GET /app-api/trade/order/get-express-map-url?id=900
```

| 项 | 值 |
|---|---|
| 权限 | 登录 + **订单归属**（非本人订单返回 `ORDER_NOT_FOUND`） |
| 响应 | `{ code: 0, data: "https://api.kuaidi100.com/tools/map/V2/..." }`（快递100 `trailUrl`） |
| 计费 | **独立计费**；进入订单详情**自动调用**；服务端缓存 1 小时 |
| 缓存 | 服务端 `express_map`，1 小时 |

错误码：

| code | 含义 | 前端表现 |
|---|---|---|
| `1_011_004_104` | 物流地图未配置发货地址/模板 | 「物流地图暂未配置，请联系管理员」 |
| `1_011_004_105` | 该订单无法生成地图（历史单无 `receiver_area_id` / 无运单） | 「该订单暂无法生成物流地图」 |
| `1_011_004_103` | 快递公司无 `kd100_code` | 「该快递公司暂不支持查询」 |
| `1_011_004_101/102` | 三方/网络失败 | 「暂时无法获取物流地图，请稍后重试」 |

前端：`OrderDetailView` 进入详情**自动加载**；成功后 `iframe` 内嵌，失败显示文案。

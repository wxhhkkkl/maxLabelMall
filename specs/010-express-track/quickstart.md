## 一、C 端：订单详情看物流（US35 / FR-253~255 / 272）

1. 后台挑一笔**已发货**的快递订单，记下运单号与快递公司。
2. 用该订单的客户账号登录 C 端，打开 `/order/{id}`。
3. ✅ 收货信息下面出现「物流信息」卡：快递公司、运单号、发货时间、
   **按时间倒序**的轨迹（最新在最上面）。
4. ✅ 打开即加载，**不需要**再点任何按钮（Q58）。
5. ✅ 找一个**未发货**订单：不出现物流卡。
6. ✅ 找一个**虚拟商品**或**自提**订单：不出现物流卡。

## 二、C 端：订单列表入口（US35 / FR-273 / SC-095）

1. 打开「我的订单」。
2. ✅ 有运单号的订单卡上出现「查看物流」，点击进入该订单详情。
3. ✅ 没有运单号的订单（含"已完成但历史无运单号"的导入单）**不出现**该入口。
4. ✅ 列表上**不显示任何轨迹文案**（不发起轨迹查询）。

## 四、失败与降级（US37 / FR-258~261 / SC-092）

| 场景 | 制造方法 | 期望 |
|---|---|---|
| 编码缺失 | 把某快递公司的 `kd100_code` 置空，查一笔该公司的订单 | 仍有公司/运单号；轨迹区「该快递公司暂不支持查询」；**不编造**轨迹 |
| 服务商报错 | 临时把 `kd100.key` 改错并重启 | 两端都显示「暂时无法获取物流信息」；订单其余内容正常 |
| 空轨迹 | 用一条刚生成、尚未揽收的运单号 | 显示「暂无轨迹信息」，不是空白 |
| 越权 | 用 A 客户 token 查 B 客户的订单 id | `交易订单不存在`，不泄露 B 的订单 |
| 服务商不可达 | 断开服务器出网 / 用代理拦截 `poll.kuaidi100.com` | 10 秒内降级提示；页面其余可用；日志有超时摘要 |
| 限频 | 同一运单 30 分钟内反复刷新 | 命中缓存；不出现 504/批量重试 |

✅ 以上任一路径，页面都**不得**出现第三方错误码、英文原文或"预计送达"。

## 五、不可回归（FR-266 / 270 / 271 / SC-094）

| 项 | 期望 |
|---|---|
| 微信小程序发货信息同步 | 发货后上送的 `expressCompany` 仍是 `code` 原值（`SF` 等），**不是** `shunfeng` |
| 小程序 / App 物流页 | 「查看物流」照常打开，轨迹正常 |
| 订单状态 / 金额 / 库存 | 查轨迹不产生任何写入；订单状态不因查看而改变 |
| 时间格式 | 轨迹时间与订单其他时间一致（epoch 毫秒 → 前端统一格式化） |

## 六、显式不验证的项（宪法原则 V 要求写明）

| 项 | 理由 |
|---|---|
| 快递100 的"订阅推送 / 轨迹回调" | 本期明确不做（spec「本期明确不做」） |
| 一单多包裹 / 多运单号 | 沿用既有单一运单模型，不在本期范围 |
| 自动识别运单号所属快递公司 | 仍由运营发货时选择 |
| 微信小程序**真实**发货同步 | 若无 `wx_lite` 支付订单 / 未配置小程序，无法端到端验证；**只做代码路径核对**（不改 `code`） |
| 安能快递的轨迹 | `kd100_code` 留空（`ane66` vs `annengwuliu` 无法确认），按"暂不支持"验证 |
| 快递100 生产套餐的计费金额 | 只验证"同一运单 1 小时内至多 1 次计费查询"（SC-091），不核对账单 |

## 八、物流地图（010 追加）

**前置**：`application-my.yaml` 配好 `kd100.map-config-key` 与 `kd100.map-from`（省市区）；
订单有 `receiver_area_id`；快递公司有 `kd100_code`。

1. C 端已发货订单详情 → **进入即自动出现** iframe（快递100 地图），无需点击。
2. 后台订单详情 → **进入即自动出现** iframe，无需点击。
3. **进入详情自动发起地图查询**；同一运单 1 小时内重复打开只出现 1 次计费查询。
4. 把 `map-from` 置空并重启 → 两端显示「物流地图暂未配置」，不出现空白 iframe。
5. 找一笔没有 `receiver_area_id` 的历史单 → 「该订单暂无法生成物流地图」。
6. 同一运单 1 小时内重复打开地图 → 只出现 1 次计费查询（`express_map` 缓存）。

**显式不验证**：自绘地图、路线动画、多发货仓、历史地址解析（本期明确不做）。

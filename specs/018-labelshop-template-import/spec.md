## Clarifications

### Session 2026-11-12

- **Q134 来源库与目标空间的准确映射？**（2026-11-12 所有者确认「确实有独立『我的模板库』」；随后以客户端二进制与完整版脚本定位）
  → **A：按客户端页签对应的 `Own_Type` 映射执行**：

  | 来源库 | 识别依据 | 实测规模 | 目标 |
  |---|---|---|---|
  | **我的模板库** | `Own_Type=12`；完整版脚本标注「我的模板」 | 44 条（云马模版 / 云马的标签 / WZ追溯） | **OWNER 个人空间** |
  | **组模板库** | `Own_Type=13`；完整版脚本标注「群组模板」 | 194 条（电信电力、服装标签等分类） | **企业空间** |
  | **企业/组织模板** | `Own_Type=1`，按公司 ID 读取 | 7 条（2 家公司） | **企业空间** |
  | **公共模板库** | `Own_Type=14`；完整版脚本标注「公共模板」 | 2019 条（含 1694 条地址、信函） | **不下载** |
  | **用户模板库** | 客户端存在该页签；精简脚本未单独读取 | 未纳入本期 | **不下载** |

  ⚠️ 精简脚本的命名不可直接采信：它把 `12` 叫「组模板库」、`13` 叫「公共模板库」、`14` 叫「用户模板库」，
  与客户端页签顺序及完整版脚本的 `Own_Type` 映射相反。本规格以**客户端页签 + 完整版映射**为准；
  实现时 MUST 用 `Own_Type` 白名单（12 / 13 / 1），其余一律不读、不写。

- **Q135 导入后的模板是否必须在桌面端直接打开？**（2026-11-12 所有者拍板）
  → **A：`.lsdx` 必须可直接打开；企业/组织私有 JSON 先原样归档并标注**。个人空间与企业空间中的
  `.lsdx` 导入后，OWNER / 持席成员在桌面端下载即可打开（桌面端已有 `.lsdx` 导入器，需在云端加载路径
  启用内容识别）；企业/组织私有 JSON 原样保存、可下载，并在结果中标注「暂不可直接编辑」，
  MUST NOT 以「成功」掩盖为可编辑。

- **Q136 导入与容量上限的关系？**（2026-11-12 所有者拍板）
  → **A：导入时不考虑个人/企业空间上限**。导入写入不受 016 的容量闸门限制，允许把空间占用推高到上限以上；
  导入后空间仍按 016 的「超配额只读」规则处理（既有内容可浏览 / 下载 / 删除，常规新增上传被拒绝，
  直到降到上限以下）；结果中 MUST 报告实际写入字节与是否超出上限。
  这是对 016 容量闸门的**显式例外**，仅适用于本导入通道；常规上传仍按 016 执行（实现口径以
  FR-491 / FR-492 为准）。

- **Q137 第三方密码能否经明文 HTTP 提交？**（2026-11-12 所有者拍板；**2026-11-13 所有者取消强制 HTTPS**）
  → **A：不强制 HTTPS**。导入入口与提交接口在 HTTP 与 HTTPS 下均可用；服务端 MUST NOT 因传输协议
  拒绝请求，前端 MUST NOT 按协议禁用或隐藏该功能。密码仍 MUST 遵守 FR-484 / FR-485 的
  非持久化、不入日志与不回显要求。

- **Q138 导入的模板是否清洗敏感字段？**（2026-11-12 所有者拍板）
  → **A：原样导入，不做服务端清洗**。模板正文（含可能内嵌的数据库连接口令、设备口令与业务数据行）
  按源端原样存入目标空间；与 Python 脚本的备份口径一致。桌面端打开并保存时会按既有规则重新脱敏。
  因企业空间对持席成员可见，使用方需知悉共享范围内的成员可能看到模板内嵌的敏感字段。
  这是对 016「模板类内容沿用 009 清洗」口径的**显式例外**，仅适用于本导入通道；常规上传仍按 016 清洗。

- **Q139 导入用的 LabelShop 账号是否必须属于 OWNER？**（2026-11-12 所有者拍板）
  → **A：任意经授权账号**。导入目标是 OWNER 的个人空间与企业空间，但 LabelShop 账号 MUST NOT
  要求与 OWNER / 企业成员身份一致，系统 MUST NOT 尝试自动核验账号归属；是否获得账号所有人授权
  由操作人在发起前确认（FR-484）。同一企业后续可使用不同账号重复导入，幂等仍按来源模板标识判定。

- **Q140 承载企业模板的文件夹默认对谁可见？**（2026-11-12 所有者拍板）
  → **A：导入时的全体持席成员**。导入新建的企业文件夹 MUST 把导入开始时全体持席成员
  写入可见名单，导入后全公司持席成员即可使用；后续新加入或新分配席位的成员 MUST NOT 被自动加入，
  需由企业管理员手动维护（016 的显式名单口径）。

- **Q141 导入中 LabelShop 会话失效怎么办？**（2026-11-12 所有者拍板）
  → **A：自动重新登录一次并继续**。检测到会话失效后 MUST 重新登录一次并从断点继续；
  若重登失败或再次失效 MUST 中止任务，保留已写入内容，并在结果中列出未处理与失败项。
  MUST NOT 为每条失败反复重登（会反复踢掉其他客户端会话）。

- **Q142 导入能否选择已有企业文件夹？**（2026-11-12 所有者拍板）
  → **A：不能选择，每次导入只新建一个专用文件夹**，名称形如 `<时间>导入`（前缀为导入开始时间、
  以「导入」结尾；具体时间格式由计划确定）。MUST NOT 允许选择或复用既有文件夹，
  MUST NOT 改动任何既有文件夹的可见名单；重复导入会再新建一个文件夹（内容仍按来源模板标识幂等跳过；
  实现口径以 FR-506 为准）。

- **Q143 企业空间导入内容的上传者记成谁？**（2026-11-12 所有者拍板）
  → **A：记为 OWNER**。企业导入内容的归属 / 上传者 MUST 为该企业 OWNER 的会员编号；
  删除权限按 016 执行（OWNER / ADMIN 可删除任意企业内容，普通成员只能删除自己上传的内容，
  因此普通成员 MUST NOT 获得导入内容的删除权）。实际执行导入的后台运营账号 MUST 在任务记录与操作日志中留痕。

- **Q144 企业停用或授权到期时导入怎么办？**（2026-11-12 所有者拍板）
  → **A：整批拒绝**。企业停用或无有效授权时 MUST NOT 发起导入，MUST NOT 只导入个人空间而跳过企业部分；
  提示原因且不产生任何内容项。已存在的历史导入内容按 016 的只读规则处理，不受影响。

- **Q145 个人会员能否自己发起历史模板导入？**（2026-11-13 所有者拍板）
  → **A：只能由运营在管理端代导**。入口在会员详情，个人会员的 C 端（门面站 / 桌面端）MUST NOT
  提供该入口；只导「我的模板库」，写入该会员的 016 个人共享空间，容量口径与企业导入一致。

- **Q146 个人「我的模板库」里的云端模板（`Own_Type=0`）怎么处理？**（2026-11-16 所有者拍板）
  → **A：导入时转成 `.lsdx`**。云端 JSON 按 `cloud_to_lsdx` 同规则转换后入库为可编辑 `.lsdx`；
  转换失败的单条记模板级失败，MUST NOT 回退为 JSON 归档。

- **Q147 个人空间的目录结构怎么保留？**（2026-11-16 所有者拍板）
  → **A：多层稳定分类树**。按来源分类路径逐级建文件夹，同名路径复用；桌面端支持新建 / 改名 /
  移动 / 删除；企业空间仍只建一个 `<时间>导入` 单层文件夹。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运营在企业详情里完成一次 LabelShop 模板导入 (Priority: P1 · US60)

运营在「软件管理 → 企业管理 → 某企业 → 成员与席位」页点击「导入历史模板」，
输入客户 LabelShop 账号与密码。系统只读地读取该账号下**被纳入迁移范围**的来源库，
把它们分别写入该企业 OWNER 的个人云模板中心与当前企业的企业云空间；不纳入范围的来源库
不下载、不写入，也不计入成功数。

**Why this priority**：这是整个特性的唯一核心价值——把老客户的历史模板资产批量搬进新平台。
没有它，其余体验（进度、结果、幂等）都没有承载对象。

**Independent Test**：用一个测试用 LabelShop 账号（各来源库都有若干条）对某企业发起导入 →
OWNER 在桌面端个人云模板中心看到属于个人空间的模板；持席成员在企业空间**本次新建的
`<时间>导入` 文件夹**看到属于企业的模板；被排除的来源库在两边都看不到。

**Acceptance Scenarios**：

1. **Given** 运营有导入权限、企业有有效 OWNER 且授权有效，**When** 输入正确的 LabelShop 账号密码并开始导入，
   **Then** 来源映射为「个人」的模板出现在 OWNER 的个人云模板中心，来源映射为「企业」的模板出现在
   当前企业的企业云空间，且都在任务结束后可被对应的人看到
2. **Given** LabelShop 账号下有被明确排除的来源库，**When** 导入完成，**Then** 这些库的模板在个人空间与企业空间
   都不存在，且结果中的成功数与实际写入数一致
3. **Given** 企业空间已有多个文件夹，**When** 导入企业模板，**Then** 系统**新建**一个 `<时间>导入` 文件夹，
   所有企业模板都落在其中；既有文件夹及其可见名单不被改动，不存在根目录内容（016 Q120 / Q142）
4. **Given** 导入的模板名称含非法字符或与目标空间已有内容同名，**When** 导入完成，
   **Then** 名称被安全处理（不覆盖既有内容、不产生无法展示的名称），且结果中可辨识原名
5. **Given** 企业没有有效 OWNER（OWNER 账号被停用 / 移出 / 不存在），**When** 发起导入，**Then** 拒绝导入并提示原因，
   不产生任何内容项

### User Story 2 - 导入过程可见、结果可核对 (Priority: P2 · US61)

导入是耗时操作（实测账号下可见约 2260 条，本期需逐条读取 / 下载其中的 245 条）。运营发起后不应被页面卡住，
应能看到进度（已处理 / 总数）与结果摘要；离开页面再回来仍能查看最近一次导入的状态与失败清单。

**Why this priority**：没有进度与结果，运营无法判断耗时导入是卡死还是仍在进行，失败也无从补救；
但它建立在 US60 的导入能力之上，可独立验收。

**Independent Test**：发起一次 200 条量级的导入（样例账号 245 条），关闭并重新打开企业详情页 →
仍能看到该任务的状态、进度与最终汇总；把其中一条制造为失败（如源端正文为空）→ 失败清单能定位到该条。

**Acceptance Scenarios**：

1. **Given** 一次导入正在进行，**When** 运营停留在企业详情页，**Then** 能看到进度并知道仍在运行
2. **Given** 导入完成，**When** 运营查看结果，**Then** 能看到成功数、按来源库的分布、跳过数、失败数与写入字节数
3. **Given** 导入有失败项，**When** 查看失败清单，**Then** 每项至少包含模板名称、来源分类与失败原因
4. **Given** 导入正在进行，**When** 运营刷新或离开页面后再回来，**Then** 仍能看到该任务的当前状态与最终结果
5. **Given** 同一企业已有导入在进行，**When** 再次发起导入，**Then** 被拒绝并提示已有任务在进行

### User Story 3 - 重复导入、超配额与凭据保护 (Priority: P3 · US62)

同一账号重复导入不应产生重复模板；导入不受个人空间与企业空间的容量闸门限制，但必须如实反映超限；
LabelShop 密码只用于本次只读导入，不得被保存、回显或写入日志与任务记录。

**Why this priority**：它决定这个功能能否安全、可重复地使用；但可以在 US60 跑通后独立补齐与验收。

**Independent Test**：同一账号连续导入两次 → 第二次不新增任何内容项；把个人空间或企业空间
填到接近上限再导入 → 导入仍完成、结果明确报告超限、导入后常规上传被拒绝；检查任务记录与日志 →
找不到密码原文。

**Acceptance Scenarios**：

1. **Given** 同一账号第一次导入已完成，**When** 立即再导入一次，**Then** 已导入的模板不被重复创建，
   结果明确显示「已存在 / 跳过」的数量
2. **Given** 目标空间剩余容量小于待导入内容，**When** 执行导入，**Then** 导入仍然完成（不受容量闸门拦截），
   结果明确显示实际写入字节、空间已用 / 上限 / 是否超出；导入后该空间的常规新增上传被拒绝，直到降到上限以下
3. **Given** 密码输入错误，**When** 发起导入，**Then** 明确提示登录失败且不产生任何内容项，
   密码不出现在提示、日志、任务记录或页面回显中
4. **Given** 导入正在进行，**When** 查看网络与服务端的对外请求，**Then** 对 LabelShop 的调用全部是只读查询 / 下载，
   不存在新增、修改、删除请求
5. **Given** 导入进行中账号密码被会话失效或网络中断，**When** 任务结束，**Then** 已写入的内容保留，
   未写入的被标记为失败或未处理，不产生残缺内容项

### Edge Cases

- **LabelShop 登录失败**：账号不存在、密码错误、账号被锁、登录接口返回非预期结构 → 任务立即失败，
  提示可辨识但不泄露密码；不产生任何内容项。
- **网络与证书**：LabelShop 旧接口的证书校验失败、请求超时、连接中断 → 单条失败不终止整批；
  登录阶段失败则整批不开始。会话失效按 Q141 自动重登一次，重登会踢掉其他 LabelShop 客户端会话，
  这是既有协议行为，规格接受。
- **账号下没有纳入范围的模板**：任务成功结束，结果为 0 条，并明确说明本次没有纳入范围的模板。
- **源端模板为空**：正文为空 / 文件不存在 → 跳过并记入失败清单，不写空内容（实测该账号有 2 条此类模板，
  均在被排除的公共模板库，不在本次导入结果中）。
- **企业/组织模板有多家公司**：LabelShop 账号下可能属于多个企业 / 组织（实测 2 家）；
  全部导入当前企业空间，按来源公司名区分分类路径，不得静默只取其中一家。
- **来源级读取失败**（STS / 某公司列表 / 个人或组分类树）：该来源记失败并在结果中说明，其余来源继续；
  全部来源失败时任务失败；不创建残缺内容（FR-490）。
- **企业授权到期或停用**：按 Q144 整批拒绝，个人空间也不写入；不得因为「后台操作」而绕过 016 的写入前提，
  也不得拆成「只导个人」的半批任务。
- **OWNER 在导入过程中被转交或移出**：以任务开始时的 OWNER 快照为准并在结果中标注；
  不得把内容写到非 OWNER 的个人空间。
- **企业席位在导入过程中变化**：文件夹可见名单按 Q140 取**导入开始时**的持席成员快照；
  任务本身 MUST NOT 因成员变化而中止，导入后新增 / 撤销的席位不自动改写名单。
- **目标空间配额不足**：导入按 Q136 不受容量闸门限制，允许占用超过上限；导入后的空间转为 016 的「超配额只读」，
  常规新增上传被拒绝，直到删到上限以下。结果必须显式报告超限情况，不得静默。
- **同名与非法名称**：允许同名内容并存（016 既有口径），但不得覆盖既有内容；
  非法字符需被安全处理，结果中仍能对应到来源名称。
- **重复导入**：同一来源模板已导入过 → 跳过，不产生重复内容；每次导入仍会新建一个 `<时间>导入` 文件夹，
  第二次导入不会并入第一次的文件夹（Q142）。
- **文件夹重名**：同一企业同一时刻只允许一个导入任务，`<时间>导入` 名称按任务开始时间生成；
  若与既有名称冲突 MUST 追加可辨识后缀，不得覆盖或复用既有文件夹。
- **并发导入**：同一企业同一时刻只允许一个导入任务；不同企业可并行。
- **服务重启 / 任务中断**：任务不得停留在「永远进行中」；重启后应标记为中断或可继续，
  已写入内容保留且不重复。
- **超大账号**：数千条模板、近百 MB 内容 → 不得因请求超时导致整批丢失，必须分批推进并保留进度。
- **凭据泄漏面**：浏览器缓存、接口返回、日志、任务记录、错误堆栈中都不得出现密码原文。
- **非加密访问**：HTTP 下与 HTTPS 行为一致，不因传输协议阻断导入（2026-11-13 取消强制 HTTPS）。
- **模板内嵌敏感字段**：按 Q138 原样导入、不清洗；企业空间可见范围内的成员可能看到模板内嵌的
  数据库口令、设备口令或业务数据行。这是所有者明确接受的风险，规格不要求服务端脱敏。
- **账号归属不明**：按 Q139 不阻断导入，由授权确认承担；同一企业可用不同 LabelShop 账号重复导入。

## Requirements *(mandatory)*

### Functional Requirements

#### A. 入口、对象与权限

- **FR-476**: 系统 MUST 在管理端「软件管理 → 企业管理 → 企业详情 → 成员与席位」提供「导入历史模板」入口；
  入口 MUST 受独立权限点控制，未授权人员 MUST 看不到入口，直接调用 MUST 被拒绝。
- **FR-477**: 导入 MUST 绑定到一个**具体企业**；导入目标固定为该企业当前 OWNER 的**个人空间**与
  该企业的**企业空间**，MUST NOT 允许指定其他会员的个人空间。
- **FR-478**: 发起导入前 MUST 校验：企业存在且启用、存在有效 OWNER、企业授权处于有效期内；
  任一不满足 MUST **整批拒绝**并说明原因，MUST NOT 只导入个人空间而跳过企业部分，且不产生任何内容项（Q144）。
  导入过程中 MUST 持续校验企业启用与授权；一旦失效 MUST 立即停止新增写入，保留已写入内容（SC-182）。
- **FR-479**: 导入 MUST 由服务端完成并裁决全部权限与配额，前端隐藏 / 显示入口 MUST NOT 被当作权限控制。

#### B. 第三方凭据与只读约束

- **FR-480**: 系统 MUST 只接受 LabelShop 的账号与密码用于**本次导入**；密码 MUST NOT 被持久化，
  MUST NOT 出现在接口响应、任务记录、日志、错误堆栈或页面回显中。
- **FR-481**: 导入对 LabelShop 的访问 MUST 是只读的：只允许查询分类、查询模板列表、读取模板正文、
  获取企业模板文件所必需的只读访问；MUST NOT 调用任何新增、修改、删除、上传、审核类操作。
- **FR-482**: 登录失败、账号无权限、接口返回异常等 MUST 给出可辨识且不泄露密码的错误；
  错误信息 MUST NOT 包含密码或可用于重放的会话凭证。
- **FR-483**: 导入任务结束（成功、失败或中断）后 MUST 丢弃本次会话凭证；MUST NOT 保留可复用的登录令牌。
- **FR-484**: 发起导入前 MUST 明确告知使用者：账号密码仅用于本次只读模板迁移，并要求确认已获得账号所有人的授权。

#### C. 来源库筛选与目标映射

- **FR-485**: 系统 MUST 按来源类型白名单识别并只读取以下三类：`我的模板库`（`Own_Type=12`）、
  `组模板库`（`Own_Type=13`）、`企业/组织模板`（`Own_Type=1`，按公司 ID）；其余来源类型
  （含 `公共模板库`、`用户模板库`）MUST NOT 读取、MUST NOT 下载、MUST NOT 写入。
- **FR-486**: `我的模板库` MUST 写入该企业 OWNER 的个人云空间（016 个人空间；
  桌面端入口为「共享空间 → 个人空间」，UI 名「个人云空间」），
  且 MUST 遵守 016 FR-400（个人空间仅本人可见、不提供任何分享）。
- **FR-487**: `组模板库` 与 `企业/组织模板` MUST 写入当前企业的企业云空间，
  且 MUST 遵守 016 FR-408 / Q120（不得根目录内容、必须属于某个企业文件夹）；容量口径见 FR-491 / FR-492。
- **FR-488**: `公共模板库` 与 `用户模板库` MUST NOT 被下载或写入；
  MUST NOT 计入成功数、不得占用任何容量。实现 MUST NOT 依赖精简导出脚本的库名（其命名与客户端页签相反）。
- **FR-489**: 每条导入内容 MUST 记录来源库、来源分类路径（如 `服装标签/上衣`）、来源模板标识与原始名称
  （记录在导入明细，与目标内容项通过 `content_id` 关联），供追溯、检索与重复导入判定；
  分类路径 MUST NOT 在导入过程中被丢弃。
- **FR-490**: LabelShop 账号下若同时存在多个企业 / 组织模板（实测 2 家），MUST 全部导入当前企业空间，
  MUST NOT 静默丢弃其中任意一家；来源公司名 MUST 保留在分类路径或来源字段中。
  来源级读取失败（STS / 某公司列表 / 个人或组分类树）MUST NOT 静默：该来源记失败并在结果中说明，
  其余来源 MUST 继续；全部来源失败时 MUST 判定任务失败，且不产生残缺内容。
  来源级失败 MUST NOT 计入模板级失败数（失败数只统计已枚举模板的失败）。

#### D. 容量、失败与幂等

- **FR-491**: 导入 MUST NOT 受 016 的容量闸门限制（Q136）：即使目标空间剩余容量不足，
  导入仍 MUST 完成并可把占用推高到上限以上；同时 MUST 按实际字节计入个人空间与企业空间的已用容量，
  保持容量数字与内容列表一致。
- **FR-492**: 导入结果 MUST 报告实际写入字节、目标空间的已用 / 上限 / 剩余以及是否超出上限；
  导入后空间 MUST 按 016 的「超配额只读」规则处理（既有内容可浏览 / 下载 / 删除，
  常规新增上传被拒绝，直到降到上限以下）。
- **FR-493**: 单条模板导入失败（正文为空、下载失败、名称异常、写入失败）MUST NOT 导致整批中止，
  任务 MUST 继续处理其余模板并汇总失败原因。登录会话失效时 MUST 自动重新登录**一次**并从断点继续；
  重登失败或再次失效 MUST 中止任务，保留已写入内容并列出未处理与失败项（Q141），
  MUST NOT 为每条失败反复重登。
- **FR-494**: 导入 MUST 幂等：同一来源模板在目标空间中已存在时 MUST 跳过，MUST NOT 创建重复内容项。
- **FR-495**: 导入 MUST NOT 修改或删除 LabelShop 源端数据，也 MUST NOT 修改目标空间中已有的同名内容。
- **FR-496**: 导入写入的内容 MUST 拥有稳定、可展示的名称与类型标记（名称归一规则由设计文档确定），
  非法字符 MUST 被安全处理；模板宽高在可获取时 MUST 被记录，无法获取时 MUST NOT 阻止导入；
  企业/组织私有 JSON MUST 以归档格式保存并按 FR-504 标注，MUST NOT 与可编辑模板混为一谈。

#### E. 长任务与可追踪性

- **FR-497**: 导入 MUST 以长任务方式执行，发起后 MUST NOT 阻塞页面；界面 MUST 能展示
  已处理数 / 总数、当前阶段与最终结果。
- **FR-498**: 系统 MUST 保存导入任务记录（企业、操作人、来源账号掩码、状态、开始 / 结束时间、
  成功 / 跳过 / 失败数、写入字节数），使页面刷新或重新进入后仍能查看最近任务与结果。
- **FR-499**: 失败清单 MUST 可查看，且每项至少包含模板名称、来源库 / 分类与失败原因；MUST NOT 只提供总数。
- **FR-500**: 同一企业同一时刻 MUST 只允许一个导入任务；重复发起 MUST 被拒绝并提示已有任务在进行。
- **FR-501**: 任务中断（服务重启、进程退出、浏览器关闭不影响服务端）后 MUST NOT 停留在「永远进行中」；
  重启后 MUST 标记为中断或可继续，已写入内容保留且不得重复导入。
- **FR-502**: 导入任务与关键操作（发起、结束、失败）MUST 可追溯（操作人、企业、时间、来源账号掩码、结果）。

#### F. 可用性与安全边界

- **FR-503**: 导入后的模板 MUST 能在其目标空间中被相应的人**看到并使用**（加载到桌面端，
  或另存为本地文件）：个人空间仅 OWNER 本人；企业空间仅按 016 的席位与文件夹可见名单开放。
- **FR-504**: 导入到个人空间与企业空间的 `.lsdx` 模板 MUST 能在桌面端对应空间中被下载
  （「下载」在本规格中指加载到编辑器并可另存为本地文件）并**直接打开**，且可另存为本地 `.lsdx` 文件
  （桌面端已有 `.lsdx` 导入能力，云端加载路径需识别并转换）；企业/组织私有 JSON MUST 原样保存、
  可下载，并在结果中标注「暂不可直接编辑」；MUST NOT 以「成功」掩盖其不可编辑性。
- **FR-505**: 导入 MUST NOT 改变企业成员、席位、授权批次、订单或计费状态；除写入目标空间的内容外，
  MUST NOT 修改任何既有业务数据。
- **FR-506**: 每次导入 MUST 新建一个专用企业文件夹，名称形如 `<时间>导入`（Q142）；
  MUST NOT 允许选择或复用既有文件夹，MUST NOT 改动任何既有文件夹及其可见名单。
  企业模板 MUST NOT 落在根目录。
- **FR-507**: 导入入口与提交接口 MUST NOT 因传输协议（HTTP / HTTPS）限制可用性；服务端 MUST NOT
  拒绝非加密请求，前端 MUST NOT 按协议禁用或隐藏该功能（Q137，2026-11-13 取消强制 HTTPS）。
- **FR-508**: 导入 MUST 原样保存模板正文，MUST NOT 执行服务端清洗（Q138）；因敏感字段导致的差异 MUST NOT
  成为拒绝导入的理由。结果摘要 MUST 标注「原样导入、未清洗」，使使用方知悉共享风险。
- **FR-509**: 导入使用的 LabelShop 账号 MUST NOT 被要求与 OWNER 或企业成员身份一致，系统 MUST NOT
  自动核验账号归属；发起前的授权确认（FR-484）是唯一前置条件。账号归属不明 MUST NOT 阻断导入（Q139）。
- **FR-510**: 导入新建的企业文件夹 MUST 把**导入开始时全体持席成员**写入可见名单（Q140）；
  导入后新增的持席成员 MUST NOT 被自动加入，需企业管理员手动维护。文件夹的可见名单变动
  MUST NOT 影响已导入内容本身。
- **FR-511**: 写入企业空间的导入内容 MUST 以该企业 OWNER 作为上传者 / 归属会员（Q143）；
  普通成员 MUST NOT 因导入而获得删除权；实际执行导入的后台运营账号 MUST 在任务记录与操作日志中留痕。
- **FR-512**: 管理端 MUST 支持运营替**个人会员**发起导入；入口 MUST 位于「会员管理 → 会员用户 →
  会员详情 → 个人空间」，并受独立权限点 `member:user:labelshop-import` 控制。个人会员 MUST NOT
  从 C 端自行使用该入口（Q145）。
- **FR-513**: 个人会员代导只读取「我的模板库」（`Own_Type=12`），写入该会员的**个人空间**；
  MUST NOT 读取组模板库 / 企业组织模板，MUST NOT 创建企业文件夹或改动企业空间。
  容量口径与企业导入一致（FR-491 / FR-492）；幂等按该会员个人空间判定；任务记录 MUST 标明
  导入对象为个人会员，并与企业任务互不占用「进行中」名额。
- **FR-514**: 个人「我的模板库」中 `Own_Type=0` 的云端模板 MUST 在导入时转换为 `.lsdx` 后写入；
  转换失败 MUST 记为模板级失败并继续其余条目；MUST NOT 以 JSON 归档代替转换结果（Q146）。
- **FR-515**: 个人空间导入内容 MUST 按来源分类路径（`父/子`）落入多层文件夹；同名路径 MUST 复用，
  MUST NOT 每次导入重复建树；会员 MUST 能对个人文件夹新建 / 改名 / 移动 / 删除，
  移动到自身或子文件夹 MUST 被拒绝（Q147）。

### Key Entities *(include if feature involves data)*

- **导入任务**：一次 LabelShop → 本平台的企业级迁移，含企业、操作人、来源账号（掩码）、状态
  （进行中 / 已完成 / 已失败 / 已中断）、开始与结束时间、成功 / 跳过 / 失败数、写入字节数；
  MUST NOT 含密码或可重放凭证。
- **导入明细**：任务中的一条模板结果，含来源库、来源分类路径、来源模板标识、原始名称、
  目标空间（个人 / 企业）与目标文件夹、结果（成功 / 跳过 / 失败）与失败原因。
- **来源模板标识**：LabelShop 侧模板的唯一标识，用于追溯与重复导入判定；与目标内容项一一对应（幂等）。
- **目标内容项**：写入 016 个人 / 企业空间的一条模板内容，含名称、字节大小、宽高、分类、格式
  （`.lsdx` 可编辑 / 企业私有 JSON 仅归档）、上传者 / 归属；个人空间与企业空间的上传者 / 归属会员
  均记为 OWNER（Q143），企业空间归属企业为当前企业。来源库、来源分类与来源模板标识记录在
  **导入明细**，通过 `content_id` 与内容项关联；实际运营账号在任务记录中留痕。
- **目标企业文件夹**：企业空间内承载导入内容的文件夹，决定哪些成员可见；每次导入由系统
  **新建** `<时间>导入`，不提供选择或复用（Q142 / FR-506）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-174**: 一次 200 条量级的导入（实测账号 245 条），运营提交后 ≤ 10 秒内看到任务已开始与进度界面；
  任务结束后展示的成功数与实际写入目标空间的内容数一致（误差 0）。
- **SC-175**: 被排除来源库的导入条数为 **0**；结果中的成功数不包含被排除库的任何条目。
- **SC-176**: 目标映射 100% 正确：个人空间内容仅 OWNER 可见（其他会员与未登录用户可见数 0）；
  企业空间内容的文件夹归属率 100%，无根目录内容。
- **SC-177**: 同一账号连续导入两次，第二次新增内容项数为 **0**；第一次成功的模板在第二次全部计入跳过
  （失败项除外）。
- **SC-178**: 导入写入字节与源端可读取字节一致（误差 0）；导入允许超出上限，结果中的已用 / 上限 / 是否超出
  100% 正确；导入后该空间的常规新增上传在超限期间 100% 被拒绝，删到上限以下后恢复率 100%。
- **SC-179**: 密码在接口响应、任务记录、日志与页面回显中的出现次数为 **0**；
  对 LabelShop 的写操作请求数为 **0**。
- **SC-180**: 任务状态与结果在页面刷新后仍可查看；失败清单对每条失败项的记录率 100%（含名称与原因）。
- **SC-181**: 单条失败不终止整批；会话失效触发一次重登后继续：
  最终成功数 = 已枚举模板数 − 跳过数 − 模板级失败数（误差 0）；来源级失败（FR-490）
  MUST NOT 计入「已枚举模板数 / 失败数」，单独记入任务 `errorMessage` 与对应 `libraries` 的 0 值。
- **SC-182**: 导入过程中企业被停用 / 授权到期后，新增写入拒绝率 100%，已写入内容不影响（按 016 只读规则）。
- **SC-183**: 导入的 `.lsdx` 在桌面端个人云空间（共享空间 → 个人空间）/ 企业空间下载（加载）后可直接打开：
  成功导入的 `.lsdx` 数 = 可打开数（失败 0）；企业/组织私有 JSON 在结果中的
  「暂不可直接编辑」标注率 100%。

## Assumptions

- **服务端不安装 LabelShop 客户端**：登录所需的客户端版本与机器标识由服务端固定配置或生成；
  不依赖运行环境的硬件信息。
- **沿用脚本已验证的只读接口**：来源分类树、模板列表、模板正文、企业模板文件；不扩展新的 LabelShop 能力，
  也不处理登录令牌失效以外的协议变化。
- **仅迁移模板**：本期只导入标签模板，不导入数据源、图片、打印记录或本地缓存中的其他内容。
- **缩略图不迁移**：016 的内容模型没有缩略图字段；模板以正文为主，结果中不承诺缩略图。
- **模板正文不做服务端清洗**：按 Q138 原样存储；桌面端打开并保存时由客户端既有规则重新脱敏。
- **导入账号不绑定身份**：按 Q139，LabelShop 账号只用于本次读取，不与会员 / 企业建立绑定关系。
- **容量计入**：个人空间按 016 FR-430、企业空间按 300 MB 共享池计入已用容量（口径见 FR-491 / FR-492）。
- **目标文件夹口径**：每次导入固定新建 `<时间>导入`，不选择 / 不复用 / 不修改既有文件夹；
  可见名单按 Q140 快照，后续新增成员由管理员手动维护（口径见 Q142 / FR-506）。
- **多个 LabelShop 企业 / 组织**：账号下发现的全部企业 / 组织模板都导入当前企业空间，
  按来源公司名区分分类路径；不按名称匹配当前企业。
- **来源库识别**：以 `Own_Type` 白名单（12 / 13 / 1）为准；精简导出脚本的库名与客户端页签相反，
  只能作为抓取方式的参考，不能作为映射依据。
- **重复导入判定依据**：来源模板标识 + 目标空间；不回写源端，也不修改源端标识。
- **桌面端配合**：本期需要桌面端在个人云模板中心与企业空间的加载路径识别 `.lsdx` 内容并转换为可编辑模板
  （本地 `.lsdx` 导入器已存在，属于跨仓库 `maxlabel` 的最小改动）；C 端门面站与小程序不改。
- **企业/组织私有 JSON**：本期只归档，不要求桌面端可编辑；后续如需转换，另行评估。
- **不涉及计费与授权变更**：导入不改变企业授权、席位、订单与个人版本。
- **明确不验证项**：LabelShop 服务端的未来协议变更、账号被厂商锁定后的申诉链路、模板在真机上的打印效果，
  本期不纳入验收；如所有者需要，另开任务。

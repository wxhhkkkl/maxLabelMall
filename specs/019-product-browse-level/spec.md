# 功能规格：商品浏览等级（与会员等级关联）

> 编号续 018：本规格从 **FR-516 / SC-195 / US63 / Q148** 接着往下排
> （018 排到 FR-515 / SC-194 / US62 / Q147）。

**Feature Branch**: `019-product-browse-level`
**Created**: 2026-11-16
**Status**: Draft
**Input**: User description: "商品加一个浏览等级，和会员等级关联"（配图：浏览等级 = 公开 / 全部登录会员 / 指定等级会员）

---

## 背景与问题

| # | 现状 | 证据 |
|---|---|---|
| E1 | 商品目前只有两类可见性控制：**企业专享**（`product_spu.enterprise_only`）与**会员授权商品**（被订阅计划引用），二者都只区分「公开商城 / 企业或订阅场景」，**无法按会员等级控制** | `ProductSpuDO#enterpriseOnly`；`ProductSpuMapper#selectPage(AppProductSpuPageReqVO, Set)` |
| E2 | 会员等级体系已存在且可运营：`member_level`（编号 / 等级 / 名称 / 升级经验 / 状态），会员通过 `MemberUserDO#levelId` 关联当前等级；管理端已有「会员等级」菜单，C 端有等级查询接口 | `MemberLevelDO`；`MemberUserDO#levelId`；`MemberLevelController`；`AppMemberLevelController` |
| E3 | 公开商城的列表 / 搜索已经在数据库查询层过滤企业专享与授权商品，详情接口对企业专享返回「商品不存在」类错误；分页总数正确 | `ProductSpuMapper#selectPage`；`AppProductSpuController#getSpuDetail`；`ProductSpuVisibilityTest` |
| E4 | C 端首页、分类、搜索结果共用同一商品分页接口；购物车 / 订单渲染走按编号批量取商品接口；营销活动（秒杀 / 拼团 / 积分 / 砍价）各自有商品列表接口 | `storefront/src/api/product.ts`；`AppProductSpuController#getSpuList`；`AppSeckillActivityController` 等 |
| E5 | 存量商品没有任何「浏览等级」属性，现有商品对所有人可见（企业专享除外） | 当前 `product_spu` 模型 |

**问题**：运营需要把部分商品只开放给特定会员等级（例如高阶会员专享资料、专属耗材包），
现在只能靠「上架 / 下架」整体开关，做不到「同一商品对不同人可见性不同」；
若放在公开商城又会向不符合条件的会员与访客暴露价格与内容。

## Clarifications

### Session 2026-11-16

- **Q148 「指定等级会员」如何判定？**（2026-11-16 所有者确认）
  → **A：后台多选具体会员等级，会员当前等级命中所选集合才可见**。不是「最低等级及以上」的门槛制，
  也不是只能单选一个等级。会员当前等级为空（尚未获得任何等级）时，不满足「指定等级」。

- **Q149 会员不符合条件时，C 端如何表现？**（2026-11-16 所有者确认）
  → **A：完全隐藏**。商品列表、搜索、详情接口都按当前登录态过滤；不符合条件的商品等同不存在，
  不出现「等级不足」占位卡片，也不返回商品名称 / 价格 / 图片；加购与下单自然无法完成。

- **Q150 与现有「企业专享」「会员授权商品」的关系？**（2026-11-16 所有者确认）
  → **A：独立叠加**。三者各自独立生效，商品必须**同时满足**所有可见性条件才展示；
  本次不改变 012 既有的企业专享口径，也不改变订阅计划商品的过滤方式。

- **Q151 会员不再满足等级后，购物车 / 收藏 / 浏览历史里已存在的受限商品如何处理？**（2026-11-16 所有者确认）
  → **A：列表隐藏 + 结算拦截**。购物车、收藏、浏览历史列表直接不返回该商品（与现有企业专享在收藏 /
  浏览历史中的处理一致）；购物车中的残留记录在提交订单时被拒绝并提示移除；**不自动删除**底层记录，
  会员等级恢复后这些记录重新可见。

## User Scenarios & Testing *(mandatory)*

### User Story 63 - 运营为商品设置浏览等级 (Priority: P1)

运营在管理端编辑商品时，在「其它设置」里看到「浏览等级」三选一：公开 / 全部登录会员 / 指定等级会员；
选择「指定等级会员」后可以从现有会员等级中勾选若干等级；保存后再次打开商品，选择与勾选项完整回显。

**Why this priority**：这是整个功能的管理入口；没有它，后续所有可见性规则都无从配置。

**Independent Test**：在管理端新建一个商品，依次切换三档并保存，重新打开详情核对；
再新建「指定等级」商品但一个等级都不勾选，确认保存被拒绝并提示。

**Acceptance Scenarios**：

1. **Given** 运营打开商品编辑页，**When** 查看「其它设置」，**Then** 看到「浏览等级」三个选项，默认选中「公开」，并有一段说明文案。
2. **Given** 运营选择「指定等级会员」，**When** 未勾选任何等级就保存，**Then** 保存被拒绝，提示至少选择一个等级。
3. **Given** 运营选择「指定等级会员」并勾选两个等级，**When** 保存后重新打开商品，**Then** 仍为「指定等级会员」且两个等级保持勾选。
4. **Given** 运营把商品从「指定等级会员」改回「公开」，**When** 保存后重新打开，**Then** 显示「公开」，此前勾选的等级不再生效。

### User Story 64 - 公开与全部登录会员的可见性生效 (Priority: P1)

访客（未登录）只能看到「公开」商品；已登录会员在「公开」之外还能看到「全部登录会员」商品；
两类商品在首页、分类、搜索、商品详情中的结果一致。

**Why this priority**：这是最常见的两档配置，直接决定未登录用户与普通会员能看到什么。

**Independent Test**：准备三个商品（公开 / 全部登录会员 / 指定等级），分别以访客、无等级会员、命中等级会员访问首页、搜索和详情，核对结果。

**Acceptance Scenarios**：

1. **Given** 商品 A 为「公开」，**When** 未登录访客浏览列表并打开详情，**Then** 可见且可正常查看。
2. **Given** 商品 B 为「全部登录会员」，**When** 未登录访客浏览列表或直接访问详情，**Then** 列表中不出现，详情按「商品不存在」处理。
3. **Given** 商品 B 为「全部登录会员」，**When** 任意已登录会员（无论是否有等级）浏览，**Then** 可见。
4. **Given** 商品 A 为「公开」，**When** 已登录会员浏览，**Then** 与访客看到的结果一致。

---

### User Story 65 - 指定等级会员的可见性生效 (Priority: P2)

「指定等级会员」商品只对当前等级在勾选集合内的已登录会员可见；等级不足的会员看不到；
会员升级到命中等级后，下一次刷新即可看到。

**Why this priority**：这是本需求的核心差异化能力，但依赖前三档基础能力先跑通。

**Independent Test**：把商品设为「指定等级会员」并只勾选等级 L2；用 L1 会员、L2 会员、无等级会员分别访问列表与详情，再把 L1 会员调整为 L2 后重试。

**Acceptance Scenarios**：

1. **Given** 商品 C 仅勾选等级 L2，**When** L2 会员浏览列表并打开详情，**Then** 可见。
2. **Given** 商品 C 仅勾选等级 L2，**When** L1 会员或未登录访客浏览列表或直接访问详情，**Then** 列表中不出现，详情按「商品不存在」处理。
3. **Given** 商品 C 仅勾选等级 L2，**When** 一个无等级会员浏览，**Then** 不可见。
4. **Given** 会员当前为 L1 且商品 C 仅勾选 L2，**When** 会员被调整为 L2 后刷新页面，**Then** 商品 C 可见（无需运营重新保存商品）。

### User Story 66 - 不符合条件的商品无法加购与下单 (Priority: P2)

即使知道商品编号，等级不足的会员或访客也无法把受限商品加入购物车、立即购买或提交订单；
已加入购物车但后来不再符合条件的商品，结算时被拦截并提示移除。

**Why this priority**：只做展示过滤而不管交易链路，会让「隐藏」变成可绕过的假象。

**Independent Test**：用不符合条件的账号直接调用加购与下单，核对被拒绝；构造购物车后调整会员等级再结算，核对拦截。

**Acceptance Scenarios**：

1. **Given** 商品 C 仅对 L2 可见，**When** L1 会员直接加购或立即购买，**Then** 服务端拒绝，提示商品不存在或不可购买。
2. **Given** L1 会员的购物车中已有商品 C，**When** 该会员进入结算并提交订单，**Then** 订单不成立，提示移除不可购买的商品。
3. **Given** 会员在符合条件的时期已经购买过商品 C，**When** 其等级后来不再满足，**Then** 历史订单、售后与订单详情仍可正常查看。
4. **Given** 会员曾收藏或浏览过商品 C，**When** 其等级不再满足，**Then** 收藏与浏览历史列表中不再出现商品 C，主动收藏或加购也被拒绝；等级恢复后记录重新出现。

### Edge Cases

- **未登录访问受限商品详情**：按「商品不存在」处理，响应中不得出现商品名称、价格、图片等任何商品信息。
- **等级不足访问受限商品详情**：同上，不区分「商品存在但无权查看」，避免泄露商品存在性。
- **会员等级为空**：只满足「公开」与「全部登录会员」，不满足任何「指定等级会员」。
- **会员等级变更**：升级或降级后，下一次请求即按新等级判定；不要求运营重新保存商品。
- **勾选的会员等级后来被停用或删除**：商品仍按已保存的等级集合判定（不会自动变成公开）；
  管理端再次保存时校验所选等级仍存在。停用 / 删除等级本身不改变商品配置。
- **指定等级但集合为空**：保存阶段就被拒绝，不允许出现「任何人都不满足」的脏数据。
- **同一商品同时是企业专享与受限等级**：必须同时满足两类条件（企业管理员也不豁免等级条件）。
- **受限商品被营销活动引用**：秒杀 / 拼团 / 积分 / 砍价等列表同样过滤，不能让活动页绕过浏览等级。
- **分页与总数**：过滤必须发生在数据查询阶段；某页可见商品不足时不得用「先取一页再剔掉」导致总数虚高。
- **同一商品在列表可见但详情被拦**：不应出现；列表与详情使用同一套服务端判定。
- **商品上下架状态**：浏览等级不改变上架 / 下架语义，下架商品即使等级命中也不可见。
- **购物车 / 收藏 / 浏览历史中的受限商品**：列表直接不返回；购物车残留记录在结算时被拦截并提示移除；
  不自动删除底层记录，会员等级恢复后这些记录重新可见（Q151）。
- **砍价记录页 / 优惠券适用商品**：前者是用户历史参与记录，按历史订单口径保留；后者属于优惠券模块既有展示，
  不在本次浏览等级过滤范围。两者均不因本特性改变。
- **印刷定制订单**：定制（014）使用独立的隐藏 SPU/SKU 与计价链路，不属于公开商品浏览，本次不改变定制下单链路。
- **已生成但未支付的订单**：按下单时的校验结果继续有效，不因会员之后降级而失效；
  这与历史订单不受影响的口径一致。
- **主动收藏 / 加购受限商品**：即使知道商品编号，服务端也 MUST 拒绝写入，不能靠个人列表绕过隐藏。

## Requirements *(mandatory)*

### Functional Requirements

**管理端配置**

- **FR-516** 商品编辑页「其它设置」MUST 提供「浏览等级」单选：**公开 / 全部登录会员 / 指定等级会员**，默认「公开」。
- **FR-517** 选择「指定等级会员」时 MUST 提供会员等级多选，等级选项 MUST 来自既有会员等级能力，MUST NOT 新建等级体系。
- **FR-518** 选择「指定等级会员」且未勾选任何等级时，保存 MUST 被拒绝，并给出可理解的提示。
- **FR-519** 商品保存后再次打开 MUST 完整回显浏览等级与所勾选等级；切回其它档位后，此前勾选的等级 MUST 不再生效。
- **FR-520** 服务端 MUST 校验所选等级存在；非法等级编号 MUST 拒绝保存。
- **FR-521** 存量商品 MUST 默认为「公开」，升级后不得有任何商品因缺少该属性而消失。

**C 端可见性**

- **FR-522** 「公开」商品 MUST 对未登录访客与所有登录会员可见。
- **FR-523** 「全部登录会员」商品 MUST 仅对已登录会员可见；未登录访客不可见。
- **FR-524** 「指定等级会员」商品 MUST 仅对已登录且当前等级命中勾选集合的会员可见。
- **FR-525** 商品列表、分类浏览、搜索结果 MUST 在服务端按当前访客 / 会员身份过滤，并保证分页总数与可见结果一致。
- **FR-526** 商品详情 MUST 在服务端按同一规则判定；不符合条件时 MUST 按「商品不存在」处理，响应中 MUST NOT 泄露商品名称、价格、图片或其它信息。
- **FR-527** 购物车、订单确认等按编号批量取商品的能力 MUST 同样过滤不符合条件的商品。
- **FR-528** 秒杀、拼团、积分、砍价等营销活动在展示商品时 MUST 同样应用浏览等级过滤。
- **FR-537** 购物车、收藏、浏览历史等个人列表 MUST 只返回当前符合浏览等级的商品；MUST NOT 自动删除底层记录，会员等级恢复后这些记录 MUST 重新可见。该规则与 FR-527 复用同一服务端判定，MUST NOT 另写一套过滤逻辑。
- **FR-538** 收藏、加购等主动写入个人列表的入口 MUST 在服务端按浏览等级校验；不符合条件 MUST 拒绝并提示商品不存在或不可操作。

**交易链路**

- **FR-529** 加购、立即购买、提交订单等交易入口 MUST 在服务端重新校验浏览等级；不符合条件 MUST 拒绝并提示商品不存在或不可购买。
- **FR-530** 已加入购物车但结算时不再符合浏览等级的商品 MUST 无法结算，并提示用户移除。
- **FR-531** 历史订单、订单详情、售后流程 MUST NOT 因商品浏览等级变化而失效。

**与既有可见性的关系**

- **FR-532** 浏览等级 MUST 与「企业专享」「会员授权商品」独立叠加：商品只有同时满足全部条件才可见；本次 MUST NOT 改变 012 既有口径。
- **FR-533** 企业管理员 / 企业 OWNER MUST NOT 豁免浏览等级条件，仍按其会员等级判定。

**一致性与权威性**

- **FR-534** 浏览等级的判定 MUST 由服务端统一裁决；管理端与 C 端 MUST NOT 各自实现可见性规则。
- **FR-535** 会员等级变更后，可见性 MUST 在下一次请求按新等级生效，MUST NOT 依赖运营重新保存商品。
- **FR-536** 浏览等级 MUST NOT 改变商品上下架、库存、价格等既有语义。

### Key Entities *(include if feature involves data)*

- **商品（SPU）**：新增「浏览等级模式」与「指定等级集合」；模式为三档之一，指定等级集合仅在模式为「指定等级会员」时有意义。
- **会员等级**：复用既有 `member_level`；商品引用其编号，不复制等级名称或等级值。
- **会员**：复用既有会员及其当前等级关联；等级为空视为无等级。
- **访客 / 登录态**：判定可见性的身份输入，由服务端从请求会话中取得。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-195** 对任意不符合条件的访客 / 会员，受限商品在首页、分类、搜索结果中的出现次数为 **0**。
- **SC-196** 对任意不符合条件的访客 / 会员，直接访问受限商品详情时返回「商品不存在」的比例为 **100%**，响应中泄露商品名称 / 价格 / 图片的比例为 **0%**。
- **SC-197** 商品列表分页的 `total` 与当前身份实际可见商品数一致；抽样 3 种身份 × 3 档配置，误差为 **0**。
- **SC-198** 管理端三种配置的保存 → 回显一致率为 **100%**；「指定等级但未勾选」的保存成功率为 **0%**。
- **SC-199** 不符合条件的账号通过加购 / 立即购买 / 提交订单成功购买受限商品的成功率为 **0%**。
- **SC-200** 会员等级调整后，新等级对应的可见性在**下一次请求**即生效（无需人工重新保存商品）。
- **SC-201** 升级后存量商品的可见性变化为 **0 个商品**（全部保持公开）。
- **SC-202** 不合格会员的购物车、收藏、浏览历史列表中，受限商品出现次数为 **0**；购物车残留记录的结算成功率为 **0%**；会员等级恢复后记录重新出现率为 **100%**。

## Assumptions

- 「会员等级」即 yudao 既有会员等级体系（`member_level` / 会员当前等级），不新建第二套等级。
- 「全部登录会员」不区分等级，只要处于登录态即可见。
- 无等级的已登录会员不满足「指定等级会员」。
- 受限商品采用「完全隐藏」，因此 C 端不需要「等级不足」占位卡片或锁定样式。
- 管理端商品列表的新增列 / 筛选条件不属于本次范围；本次只做编辑页配置。
- C 端 Web 门面站、小程序 / App 共用同一服务端判定，服务端过滤后各端自动一致，不要求各端分别改造商品卡片。
- 公开商品在未登录状态下可正常浏览与详情。
- 企业专享商品仍不进入公开商城，订阅计划商品仍只在续费 / 采购场景展示，这两条既有规则不变。
- 本特性范围只覆盖公开商城商品浏览与交易；砍价记录页、优惠券适用商品展示、印刷定制下单链路不在范围内
  （具体口径见 Edge Cases）。

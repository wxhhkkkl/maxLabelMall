## 一、前置条件

1. 后端以本地单体启动（`yudao-server`，48080），管理端 `pnpm dev`。
2. 测试库已执行 `sql/mysql/042-license-dashboard.sql`（新表 + 加列 + 菜单权限）。
3. 准备数据（测试库）：
   - 会员 A：个人订阅未到期（专业版）
   - 会员 B：只有企业席位（无个人订阅）
   - 会员 C：订阅昨天到期
   - 企业 D：2 个有效批次中 1 个已折算（验证只算有效批次）
   - 企业 E：已购买席位但一个都没分配
4. 用超管（或已勾选 `member:license:query` + `member:license:gift` 的角色）登录管理端。

## 二、看板与口径

| # | 操作 | 期望 |
|---|---|---|
| 1 | 打开「软件管理 → 授权看板」 | 三张卡片都出数且横向对齐；当年卡片按「新获得 / 延续」分两组、各有口径文案，不是笼统的"新增客户" |
| 2 | 对照 `member_subscription` 里未过期的会员数 | 个人有效授权数**一致**（B 不计入个人，C 不计入） |
| 3 | 对照企业列表 | 企业有效授权数含 **E**（有批次、未分席位），不含已停用企业；企业 D 的席位数只算未折算批次 |
| 4 | 点任一数字 | 跳到明细并带上对应筛选（FR-543） |
| 5 | 跨年核对 | 把某会员的续费行 `create_time` 改到去年 → 该会员从「新获得/延续」移出（合计随之变化） |

**Q163 卡片口径（2026-11-17）**：

- 三张卡片标题、指标标签、数字横向对齐；卡片等高。
- 「个人授权」只有「订阅会员」一个数字，**不再**显示「席位会员」；点它下钻只列订阅会员。
- 当年卡片按「新获得授权 / 延续授权」两组，各自显示「个人会员 / 企业席位 / 合计」，
  合计 = 个人会员数 + 企业席位数（单位不同，不是客户数）。
- 造数验证：今年首次购买的企业 A 批 10 席、去年老企业 B 今年新增 6 席 →
  「新获得·企业席位」=10、「延续·企业席位」=6；退款 / 折算批次不计入席位。

**不该发生**：把注册会员数当作「当年新增客户数」；把只有企业席位的 B 显示成「未订阅」。

## 三、明细

| # | 操作 | 期望 |
|---|---|---|
| 6 | 搜会员 A | 显示来源「订单购买」、到期日、剩余天数 |
| 7 | 搜会员 B | 来源含「企业席位」，**不是**「未订阅」 |
| 8 | 搜一个既有个人订阅、又在企业有席位的会员 | 两条来源各自到期 + **合并到期取较晚** |
| 9 | 状态筛「已过期」 | 会员 C 出现，剩余天数显示 **0**，并另显示「已过期 N 天」（`expiredDays`），不把负数塞进剩余天数 |
| 10 | 关键字搜手机号 / 企业名 | 都能命中 |

## 四、赠送（重点）

| # | 场景 | 期望 |
|---|---|---|
| 11 | 给会员 A 送 1 个月 | 到期日**从原到期日顺延**一个月；客户侧（C 端/桌面端）刷新后到期日同步变化 |
| 12 | 给会员 C（已过期）送 1 个月 | 从**今天**起 1 个月 |
| 13 | 不填理由直接提交 | 被拦下，提示必须填写理由 |
| 14 | 会员 A 剩 10 个月，选「3 个月」 | 「3 / 6 / 12」**置灰**，只能选 1 个月，并提示"最多还能赠送 2 个月" |
| 15 | 给企业 E（有批次、未分席位）送 5 个席位 | 席位总数 +5，到期日不变；TAB 里能看到这笔记录 |
| 16 | 给企业 D 送 3 个月时长 | 企业到期日顺延 3 个月，席位数不变 |
| 17 | 给一家**没有任何有效批次**的企业送 5 个席位 | 必须同时填时长；提交后出现一条赠送批次，席位可用 |
| 18 | 给已停用的企业赠送 | 被拒并提示先启用 |
| 19 | 连点两次提交 | 只产生一笔赠送记录、只延长一次 |
| 20 | 赠送记录页签按操作人 / 对象 / 时间筛 | 都能筛到；记录里有理由、前后到期日 |
| 21 | 未勾 `member:license:gift` 的角色 | 看不到赠送按钮；直接调接口返回 403 |
| 22 | 点看板顶部「赠送授权」，搜一个**从未有过授权**的会员 | 能选到该会员（状态「无授权」、当前到期「无有效授权」）；送 1 个月从**今天**起算 |
| 23 | 同入口搜一个**从未购买过**的企业，送 5 个席位 | 弹窗要求同时选时长（"该企业暂无有效授权…"）；提交后出现赠送批次与席位（Q162 / Q157） |
| 24 | 同入口按客户类型 / 关键字筛选 | 个人、企业分别能筛出；停用企业标注「已停用」，提交赠送被拒并提示先启用 |

## 六、上线顺序（执行前必须得到所有者确认）

> ⚠️ 宪法原则 VI：**任何时候不自动发版**。以下步骤只是顺序说明，不等于授权。

1. 执行 `sql/mysql/042-license-dashboard.sql`（新表 + 加列 + 放宽可空 + 菜单/权限点）
2. 发布后端（`yudao-server`）
3. 发布管理端（`yudao-ui-admin-vue3`）
4. 给需要的角色勾上 `member:license:query` / `member:license:gift`

**回滚**：

- 代码：回滚 jar 与管理端静态资源（发版脚本自带备份）。
- 数据库：`member_license_grant` 可保留（只增不改，留作审计）；`license_grant_id` 列可留（可空）。
  **不建议**把放宽为可空的列改回 `NOT NULL` —— 一旦已有赠送行，改回去会失败。
- 菜单：把「授权看板」菜单与两个按钮权限置为停用即可关闭入口（后端接口的 `@PreAuthorize` 仍会拦）。
- ⚠️ 回滚**不会**撤回已赠送的授权 —— 赠送是既成事实，要纠正只能再送一次对冲（Q154：不可撤销）。

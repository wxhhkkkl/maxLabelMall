**Created**: 2026-11-16
**Status**: Draft
**Input**: User description: "管理后台软件管理增加授权看板，查看当前所有个人用户和企业用户的授权数量，可以查看当年新增客户数量，可以查看每个用户的授权时间，可以有按钮进行授权的赠送，授权赠送需要填写理由留下记录"

## 背景与问题

运营今天要回答三个问题，得在三个地方拼凑，而且**没有一个问得到准确答案**：

| 想回答的问题 | 今天怎么做 | 为什么答不准 |
|---|---|---|
| 现在有多少个人客户在用授权？ | 会员列表看「订阅状态」列 | 该列**只按个人订阅行**判断（`MemberUserController` 只取 `member_subscription`），**只有企业席位的人会显示「未订阅」** |
| 现在有多少企业客户、占了多少席位？ | 挨个点开「企业管理 → 某个企业」 | `maxlabel_org` 列表没有席位数与到期日，要逐家进去看 |
| 今年新增了多少客户？ | 商城首页的「新增用户」 | 那是**注册会员数**，不是「获得了授权的客户数」—— 注册了几十个、一个没买也是同一个数字 |

更关键的是：**系统没有任何「补发 / 赠送授权」的通道**。今天授权的唯一发放入口是支付成功回调
（按订单项命中套餐后发放）；企业授权批次也只能由订单产生。客户投诉补偿、售前试用、销售口头承诺
的赠送，运营在后台**无路径可走**，只能让客户重新下单再由财务线下冲账。

本特性要落的是一个**授权看板**：把「谁有授权、到什么时候、今年新增多少」一次看清，并给运营一个
**必须写明理由、且留下记录**的赠送入口。

## Clarifications

### Session 2026-11-16（所有者拍板）

- **Q152 授权赠送支持哪些对象、送的是什么？**
  → **C：个人会员送时长；企业既可送席位、也可送时长。**
  背景：看板同时覆盖两类客户；若只能补个人，企业客户的投诉补偿仍要绕回"下单 + 财务冲账"。

- **Q153 「当年新增客户」按什么口径统计？**
  → **当年「新获得授权」与「延续了授权」的客户**：今年内因购买、续费、赠送而**首次获得**或
  **被延长**授权的客户，个人按会员去重、企业按企业主体去重后相加。
  **不含**只注册、从未获得授权的会员；也不含去年就有授权、今年没有任何变动的客户。

- **Q154 赠送要不要设上限、能不能撤销？**
  → **B：设时长上限，不可撤销。** 两条硬上限：
  ① **单次**赠送时长 ≤ 12 个月；
  ② 赠送后该账户的**剩余有效时长** ≤ 12 个月（即赠送后到期日不得晚于「今天 + 12 个月」）。
  超出时 MUST 拦下，并提示当前还能赠送的最大时长。赠送**不可撤销**，只能留痕；填错只能再送一次对冲。
  ⚠️ **2026-11-19 修订**：「不可撤销」已被 **Q164** 推翻 —— 现在允许撤回，口径见 Q164 与 FR-559~562；
  本条保留，只作为当时的来龙去脉。

- **Q161 「只有企业席位、没有个人订阅」的会员怎么算？**（2026-11-16 所有者裁定）
  → **B：明细照常列出（来源=企业席位），看板把个人拆成「订阅会员 / 席位会员」两栏**；
  对账口径改为「订阅会员 + 席位会员 + 企业有效」。这样 US68-2 与 SC-204 可以同时成立。

- **Q155 「当年新增客户数」合并成一个总数，还是把「新获得」与「延续」拆开？**
  → **B：拆成两个并排的数字**——「今年新获得授权」「今年延续授权」，**另给合计**；
  三者都按客户去重（同一客户同年既新获得又延续，在合计里只算 1 个）。
  理由：拉新与续费是两种业务含义，合并成一个数既看不出增长来源，汇报时也容易被误读成"全是新客"。

- **Q156 买了席位但还没分配给任何成员的企业，算不算「有效企业授权」？**
  → **A：算。** 只要企业启用且有有效批次就计入，**不看席位是否已分配** —— 席位空着是分配进度问题，
  不是授权失效。注意区分：会员**个人经企业席位获得权益**仍要求席位未撤销（012 的判定不变）。

- **Q157 赠送给企业的席位，有效期跟着什么走？**
  → **A：跟企业"最晚到期"的有效批次同寿命。** 企业当前没有有效批次时，赠送席位 MUST 同时给一段时长
  （席位才有地方生效），该时长受 Q154 的 ≤12 个月上限约束。

- **Q158 赠送时运营要不要选套餐/版本？**
  → **不选，版本由客户类型固定：个人会员只能赠送「专业版」，企业会员只能赠送「企业版」。**
  运营只需填时长（企业送席位时另填席位数）。赠送不得让任何人降级（有效版本仍取最高档）。

- **Q159 赠送记录放在哪里看？**
  → **A：看板内的独立「赠送记录」页签**，列出全部赠送并支持按被赠对象 / 操作人 / 时间范围筛选。

- **Q160 赠送时长是运营自己填，还是从固定档位选？**
  → **A：固定档位 1 / 3 / 6 / 12 个月。** 与在售套餐的周期口径一致；超出剩余额度的档位置灰，
  不允许"填了才被拒"。

- **Q162 赠送只能送给「已有授权」的客户吗？**（2026-11-17 所有者追加）
  → **不能。赠送是独立功能，对象范围 MUST 覆盖全部个人会员与全部企业，不限是否已有授权。**
  看板顶部 MUST 提供独立的「赠送授权」入口：先按客户类型 / 关键字筛选并选择对象，再填写赠送内容；
  客户明细行内的赠送入口保留。从未有过授权的客户按「无有效授权」处理（从当天起算，
  见 FR-548 最后一条），MUST NOT 因为"选不到 / 没有可挂靠的既有授权"而无法赠送。

- **Q163 看板卡片口径调整**（2026-11-17 所有者追加，修订 Q155 / Q161 的**展示**部分）
  → ①「个人授权」卡片**只显示订阅会员数**；席位会员不再在看板单独展示（仍保留在明细中，
  来源=企业席位，且不混进订阅会员数）。
  ②「当年」卡片改为按「个人会员数 + 企业席位数 + 合计」展示，**新获得授权与延续授权各自拆分**：
  - **个人会员数**：沿用 FR-542 的去重口径（当年首次订阅 / 当年续费或赠送延长）；
  - **企业席位数**：企业当年**新增授权批次**（`maxlabel_org_license.create_time` 落在当年、
    未退款、未折算）的 `seats_total` 之和；按企业**史上第一批**是否在当年归入「新获得 / 延续」；
  - **合计 = 个人会员数 + 企业席位数** —— 两者单位不同（人 vs 个），合计**不是客户数**，
    卡片标题 MUST NOT 再写「按客户去重」。
  ③三张卡片 MUST 采用同一套「标题 + 指标（小标签 + 数字）」结构，横向等高对齐。

- **Q164 赠送能不能撤回？**（2026-11-19 所有者追加，**推翻 Q154 的「不可撤销」**）
  → **能，但只撤最近一笔。** 具体口径：
  ① 在「赠送记录」页签对某笔赠送点「撤回」，必填**撤回理由**后立即生效；
  ② **只能撤回该对象最近一笔**、且此后没有任何新的赠送 / 购买 / 折算的赠送；更早的赠送
    已被后续权益覆盖，按增量回退会算错，MUST 拦下；
  ③ 个人：删除这笔赠送产生的订阅行（权益 = 未删除订阅的 `MAX(end_time)`，删掉即精确还原）；
     企业送席位：回减批次 `seats_total`；企业送时长：回退批次 `end_time` 与 `period_months`；
     由这笔赠送新建的批次：整批撤回；
  ④ 批次上还有**已分配席位**时 MUST 拦下，让运营先去企业管理撤销席位分配 ——
     MUST NOT 连带收回成员权益；
  ⑤ 记录本身**不删除**，只追加撤回时间 / 撤回人 / 撤回理由；赠送记录页签显示「已撤回」；
  ⑥ 权限**复用** `member:license:gift`（不新增权限点，也不新增菜单数据）；
  ⑦ 撤回错了**不能反悔**，只能重新赠送（操作日志与赠送记录都留痕）。

## User Scenarios & Testing *(mandatory)*

### US67 - 一眼看清当前授权规模 (Priority: P1)

运营上班第一件事：打开「软件管理 → 授权看板」，看到当前**个人订阅会员数**、**企业有效授权数**
（附企业席位已分配 / 总席位），以及当年授权：**新获得 / 延续**两组，各自给出
**个人会员数 / 企业席位数 / 合计**（Q163）。数字旁边能点进去看到对应的人。

**Why this priority**：这是「看板」之所以叫看板的理由，也是回答所有者最常问的三个数字的地方。
没有它，后面的明细与赠送都没有落脚点。

**Independent Test**：造出「个人有效授权」「只有企业席位的人」「已过期订阅」「今年新增」「去年老客户」
五类数据后打开看板，核对订阅会员数、企业有效数与当年的分项数字（Q163）；再点数字旁的入口，
确认明细与数字一致。

**Acceptance Scenarios**：

1. **Given** 存在 10 个会员的个人订阅尚未到期、3 个会员的订阅已过期，
   **When** 打开授权看板，**Then** 个人有效授权数显示 10（不含已过期的 3 个）。
2. **Given** 存在 2 家企业：A 有 20 席位其中 15 个已分配，B 有一批已过期、一批有效，
   **When** 打开看板，**Then** 企业有效授权数显示 2，席位显示「15 / 20」，且 B 的席位数只算有效批次。
3. **Given** 某会员个人订阅已过期，但他在企业 A 有未撤销席位且企业有效，
   **When** 看板按「有效授权」统计，**Then** 该会员**计入**企业侧，而不计入个人侧（不重复计数）。

### US68 - 逐个客户看授权到什么时候 (Priority: P2)

运营在明细里按客户查：每个个人会员、每家企业一行，显示**授权起、止时间、剩余天数、来源**
（订单购买 / 运营赠送 / 企业席位），并能按客户类型、授权状态、关键字筛选。

**Why this priority**：客服每天被问「我的授权到几号」。有了明细，一次查询就能回答，
不必在会员详情、企业详情之间来回跳。

**Independent Test**：给定上述五类数据，逐个关键字搜索、按状态筛选，核对每行的起止时间与剩余天数
是否与该会员/企业当前实际生效的权益一致；个人+企业双来源的会员，剩余天数取**较晚到期**。

**Acceptance Scenarios**：

1. **Given** 一个既有个人订阅、又在企业有席位的会员，**When** 在明细中查看他，
   **Then** 显示两条来源及其各自的到期日，并给出**合并后的实际有效到期日**（取较晚）。
2. **Given** 一个只有企业席位、从没买过个人订阅的会员，**When** 在明细中查看他，
   **Then** 显示为「有效（企业席位）」而不是「未订阅」。
3. **Given** 订阅昨天到期，**When** 用「已过期」筛选，**Then** 他能被筛出来，`剩余天数` 显示 **0**，
   并另显示「已过期 1 天」（不把负数塞进"剩余天数"里）。

### US69 - 赠送授权并留下记录 (Priority: P3)

运营在明细行内、或从看板顶部的独立「赠送授权」入口（可筛选**全部**个人与企业，不限是否已有授权）
选择一个客户，选择赠送内容（个人送时长 / 企业送席位 / 企业送时长）、
**填写理由**（必填），确认后**立即生效**；之后能在看板里查到这笔赠送：谁在什么时候、送给谁、
送了什么、什么理由。

**Why this priority**：这是把「线下口头承诺」变成「系统里有据可查」的唯一手段；没有它，
看板只能看、不能补救。

**Independent Test**：对一个已有有效授权的个人客户赠送时长，确认到期日从原到期日**顺延**；
对一个已过期客户赠送，确认从**当天**开始；对一家企业分别赠送席位与时长，确认席位数、到期日各自变化；
再在赠送记录里核对操作人、时间、对象、内容与理由；最后用客户账号查看权益，确认已生效。

**Acceptance Scenarios**：

1. **Given** 客户 A 的个人授权 2027-01-31 到期，**When** 赠送 1 个月，
   **Then** 新到期日为 2027-02-28（按自然月顺延，不覆盖原有剩余）。
2. **Given** 客户 B 的授权已于上月过期，**When** 赠送 1 个月，**Then** 从**当天**起 1 个月生效。
3. **Given** 运营没填理由，**When** 点确认，**Then** 提交被拦下并提示「必须填写赠送理由」。
4. **Given** 赠送成功，**When** 查看赠送记录，**Then** 能看到操作人、操作时间、被赠对象、赠送内容、
   理由，以及**赠送后的新到期日**。
5. **Given** 赠送过程中出现异常（例如保存失败），**When** 运营重新打开看板，
   **Then** 既没有产生授权，也没有留下半截记录。
6. **Given** 企业 C 有 20 个席位、2027-06-30 到期，**When** 赠送 5 个席位，
   **Then** 席位总数变为 25、到期日仍是 2027-06-30。
7. **Given** 企业 C 到期日为 2027-06-30，**When** 赠送 3 个月企业时长，
   **Then** 到期日顺延为 2027-09-30，席位数不变。
8. **Given** 客户 D 的授权还剩 10 个月，**When** 打开赠送弹窗，
   **Then** 只有「1 个月」可选（3 / 6 / 12 会超过 12 个月上限），并提示「最多还能赠送 2 个月」。
9. **Given** 个人客户原本是「标准版」，**When** 赠送 1 个月，**Then** 他的有效版本变为「专业版」
   （个人赠送固定专业版）；**Given** 企业客户赠送席位或时长，**Then** 版本为企业版。

### Edge Cases

- **同一会员既有个人订阅又有企业席位**：看板「个人有效授权数」只数个人来源，「企业有效授权数」
  按企业数 + 席位数计；会员的实际到期日取两者较晚（沿用 012 的口径），**不重复计数**。
- **企业席位没分完**：企业计 1 个「企业客户」，但席位数按「已分配 / 总数」展示，不把空位算成客户。
- **企业停用**：状态为停用的企业，其企业授权与席位都**不计入「有效」**，也不接受赠送（Q156 / FR-541）。
- **跨年边界**：「当年」= 自然年 1 月 1 日 00:00 至查询时刻；12 月 31 日 23:59 新增的客户算当年。
- **赠送对象不存在 / 已注销**：不允许赠送，给出明确提示。
- **连点两次确认**：只生效一次（幂等），不会送两倍时长。
- **赠送超上限**：单次 > 12 个月，或赠送后剩余 > 12 个月，都必须拦下并告诉运营"最多还能送多少"。
- **客户已接近上限**：剩余 11 个月时最多只能送 1 个月；剩余已满 12 个月时不能赠送时长（但仍可赠送企业席位）。
- **企业已停用**：不接受赠送，提示先启用企业（停用企业的席位不计入有效，送了也不生效）。
- **企业没有任何有效批次**（新客户或全部过期）：赠送仍要能落地，按新起一段授权处理；
  此时赠送席位必须同时填时长（Q157），否则席位没有可依附的有效期。
- **已退款客户**：当年有退款也照样计入「新获得 / 延续」（退款只标记不回收授权）；
  但它若已过期，则**不计入**「当前有效授权数」—— 两个问题分开判。
- **看板为空库**：显示 0 与空列表，不显示报错或空白页。
- **无权限运营**：看不到赠送按钮，直接调用接口也被拒（不能只靠前端隐藏）。

## Requirements *(mandatory)*

### Functional Requirements

**看板与口径**

- **FR-539**：「软件管理」下 MUST 有「授权看板」入口，且为**独立权限点**（菜单可见性 + 赠送按钮分开授）。
- **FR-540**：看板 MUST 展示：**订阅会员数**、**企业有效授权数**（附已分配 / 总席位），
  以及**当年授权**：新获得 / 延续两组，每组 MUST 分别给出 **个人会员数、企业席位数、合计**（Q163 / FR-542）。
  席位会员数 MAY 仍由接口返回，但看板 MUST NOT 再单独展示（明细中照常可见）。
- **FR-541**：「有效授权」MUST 以**当前时刻**判定，且**个人口径与企业口径不同**（Q156）：
  - **订阅会员**：订阅到期时间晚于当前时刻。
  - **席位会员**（Q161 / Q163）：有有效企业席位、**但**没有未过期个人订阅的会员 —— 单独计数，
    **不混进订阅会员数**；Q163 起不再在看板卡片单独展示，但 MUST 仍出现在明细中。
  - **企业**：企业**启用**且**至少有一个有效批次**（未过期、未退款、未折算）即计入，
    **不看席位是否已分配**；已过期、已作废、已退款、已折算的不计入。
  - ⚠️ 但**会员个人经企业席位获得的权益**仍沿用 012 的判定（席位未撤销 + 企业启用 + 有效批次）——
    两者是不同的问题：前者问"这家企业是不是有效客户"，后者问"这个员工现在能不能用"。
- **FR-542**：「当年授权」MUST 拆成**「新获得授权」与「延续授权」两组**，每组 MUST 分别给出
  **个人会员数、企业席位数、合计**（Q163，修订 Q155 的展示口径）：
  - **个人会员数**：统计区间内**首次**订阅的会员（新获得）/ 订阅**被延长**的会员（延续，续费或运营赠送都算），
    按会员去重；MUST NOT 把「仅注册未获授权」的会员算进来；
  - **企业席位数**：当年**新增授权批次**（`maxlabel_org_license.create_time` 落在当年、未退款、未折算）
    的 `seats_total` 之和；企业**史上第一批**在当年 → 计入「新获得」，早于当年 → 计入「延续」；
  - **合计 = 个人会员数 + 企业席位数**（两者单位不同，MUST 明确标注；合计 MUST NOT 被称作「客户数」）。
  页面 MUST 逐个标注口径名称，MUST NOT 与「注册会员数」混称。
  **已退款客户照常计入个人会员数**（2026-11-16 分析裁决）：退款在既有模型里**只标记、不回收授权**
  （订阅行的 `refunded` 仅作标记）；但企业席位按**有效批次**口径求和，退款 / 折算批次不计入席位。
  ⚠️ 这与「当前有效」是两个问题：退款客户可以计入当年会员数，但若其授权已过期，就**不计入**有效授权数。
- **FR-543**：看板数字 MUST 可下钻到明细（点数字 → 带着对应筛选条件打开明细）：
  个人卡片 → 个人 + 订阅会员；企业卡片 → 企业；当年卡片 → 全部客户（当年没有时间筛选，下钻不带年份条件）。

**明细**

- **FR-544**：明细 MUST 以一个客户一行展示：客户类型（个人 / 企业）、标识（昵称或企业名 + 手机号/负责人）、
  **授权开始时间、到期时间、剩余天数、来源**（订单购买 / 运营赠送 / 企业席位）。
- **FR-545**：明细 MUST 支持按**客户类型**（个人 / 企业）、**授权状态**（有效 / 已过期）筛选，
  以及按**关键字**（会员昵称、手机号、企业名）检索，并分页。
- **FR-546**：对**同时有个人订阅与企业席位**的会员，明细 MUST 分别列出来源与到期日，并额外给出
  **合并后的实际有效到期日**（取较晚）；只有企业席位的会员 MUST NOT 被展示为「未订阅」。
- **FR-547**：明细与看板数字 MUST **同源同口径**：明细按「有效」筛选出的条数
  = 「订阅会员 + 席位会员 + 企业有效」（Q161 的分栏口径）。只有企业席位的会员 MUST 在明细中出现，
  即使 Q163 起看板卡片不再单独展示席位会员数。

**赠送**

- **FR-548**：授权赠送 MUST 支持三类内容（Q152）：**个人会员送时长**、**企业送席位**、**企业送时长**。
  - 赠送对象的可选范围 MUST 覆盖**全部注册会员与全部企业**，MUST NOT 限于已有授权的客户（Q162）；
    看板顶部 MUST 有独立赠送入口（先选对象、再填赠送内容），明细行内入口保留。
    赠送对象列表 MUST 支持按客户类型 / 关键字筛选并分页。
  - **个人送时长**：运营从**固定档位 1 / 3 / 6 / 12 个月**里选一个（Q160），不填任意月数；
    不选套餐、不选版本，**版本固定为「专业版」**（Q158）。不产生订单、不产生收款。
  - **企业送席位**：企业可用席位数 + N，到期日不变；**送出的席位与企业"最晚到期"的有效批次同寿命**（Q157）。
    企业**当前没有任何有效批次**时，赠送席位 MUST 同时填写时长（否则席位无处生效），该时长同样受 FR-555 上限约束。
    版本固定为「企业版」。
  - **企业送时长**：企业有效期顺延 N 个月，席位数不变；版本固定为「企业版」。
  - 赠送 MUST NOT 让任何客户**降级**：客户的有效版本仍按既有规则取"当前有效授权里的最高档"，
    一次专业版赠送不会把已经更高版本的客户降下来。
  - 对**当前没有任何有效授权**的客户（个人从未有过订阅 / 企业无有效批次），赠送 MUST 照样能落地，
    视为新起一段授权，MUST NOT 因"没有可挂靠的既有授权"而拒绝。
- **FR-549**：赠送 MUST 要求填写**理由**，非空且不超过 255 字；未填时 MUST 阻止提交并明确指出。
- **FR-550**：赠送成功后 MUST 立即生效（客户下一次读取权益即为新值），不依赖发版、人工刷新或重新登录。
- **FR-551**：赠送起点 MUST 与既有续费口径一致：客户**当前仍有效**时从**原到期日顺延**；
  已过期或从未有过授权时从**当天**开始。MUST NOT 覆盖或缩短客户原有的剩余时长。
- **FR-552**：每次赠送 MUST 留下**不可修改**的记录：操作人、操作时间、被赠对象、赠送内容、
  理由、赠送前的到期日、赠送后的到期日。
- **FR-553**：赠送记录 MUST 作为看板内的**独立页签**展示（Q159），列出全部赠送，并 MUST 支持按
  **被赠对象、操作人、时间范围**筛选；每条记录 MUST 能与操作日志互相印证。
- **FR-554**：赠送 MUST 是**原子**的：失败时不得产生授权的变更，也不得留下无对应授权的记录。
- **FR-555**：赠送时长 MUST 受两条上限约束（Q154），**个人与企业时长赠送同样适用**：
  ① **单次**赠送时长 ≤ 12 个月（档位最高即 12 个月）；② **赠送后剩余有效时长** ≤ 12 个月
  （即赠送后到期日不得晚于「今天 + 12 个月」）。任一条不满足时 MUST 拦下提交，
  并告诉运营**当前最多还能送多少**；**超出额度的档位 MUST 置灰**，不让运营选了才知道不行
  （例如还剩 10 个月时，「3 / 6 / 12」都不可选，只能选 1 个月）。~~赠送 MUST NOT 被撤销（只能再赠送对冲）~~
  → **2026-11-19 起改为可撤回**，见 Q164 / FR-559~562。
  **「剩余月数」的换算口径**（2026-11-16 分析裁决）：`剩余月数 = ceil(剩余天数 / 30)`，
  `最多还能送 = clamp(12 − 剩余月数, 0, 12)`；前端置灰与后端校验 MUST 用同一个算法
  （单一实现，见 tasks T061）。
- **FR-556**：赠送 MUST 有服务端权限校验，MUST NOT 只靠前端隐藏按钮。

**赠送撤回（Q164，2026-11-19 追加）**

- **FR-559**：赠送记录 MUST 支持**撤回**：运营在「赠送记录」页签对某笔赠送填写理由后撤回，
  撤回 MUST 立即生效（客户下一次读取权益即为赠送前的值），不依赖发版或重新登录。
- **FR-560**：撤回 MUST 只允许**该对象最近一笔**赠送：该客户此后又有过新的赠送、购买或折算时 MUST 拦下，
  并提示"只能撤回最近一笔"。理由：更早的赠送已被后续权益覆盖，按增量回退会算错到期日。
- **FR-561**：撤回 MUST 精确还原赠送前的授权状态：个人删除这笔赠送产生的订阅行；
  企业送席位回减批次 `seats_total`、送时长回退批次 `end_time` 与 `period_months`；
  由这笔赠送新建的批次整批撤回。批次上已有**已分配席位**时 MUST 拦下，
  提示先去企业管理撤销席位分配，MUST NOT 连带收回成员权益。
- **FR-562**：撤回 MUST 填理由（非空、≤255 字）并留痕：记录本身不删除，
  只追加撤回时间、撤回人、撤回理由；赠送记录页签 MUST 显示「已撤回」状态与撤回人/理由。
  权限复用 `member:license:gift`（能送的人才能收，所有者在 2026-11-19 明确不新增权限点）。

**边界**

- **FR-557**：看板与明细 MUST NOT 展示会员的模板内容、打印记录等业务数据（沿用 012 对企业管理员的边界）。
- **FR-558**：本特性 MUST NOT 改变现有权益判定规则（个人 ∪ 企业取较晚），也 MUST NOT 影响支付回调的发放路径。

### Key Entities

- **授权（个人）**：某会员在某段时间内有效的个人订阅；同一会员可有多段（续费），
  有效与否由到期时间推导。
- **企业授权**：企业与「批次（席位总数、起止时间、是否退款/折算）」以及「席位（分配给谁、是否撤销）」的组合；
  企业的有效席位与到期日由有效批次派生。
- **赠送记录**：一次运营赠送的留痕 —— 对象（个人会员 / 企业）、内容类型（个人时长 / 企业席位 /
  企业时长）、数量、理由、操作人与时间、赠送前后的到期日。
- **看板指标**：个人有效授权数、企业有效授权数（含席位数），以及当年的**三个客户数**
  ——「新获得授权」「延续授权」「合计」（按客户去重）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-203**：运营从登录到看到「某客户的授权到期日」不超过 **3 次点击**（看板 → 明细 → 该客户）。
- **SC-204**：明细按「有效」筛选出的条数 = 订阅会员 + 席位会员 + 企业有效，**完全一致**（对账零差异）。
  席位会员自 Q163 起不在看板卡片单独展示，但仍在明细中（来源=企业席位），对账口径不变。
- **SC-205**：任何一笔赠送都能在 **30 秒内**追到「谁、何时、给谁、送了什么、为什么」（记录可检索）。
- **SC-206**：赠送成功后，客户侧权益在**下一次读取**即为新到期日（无需发版、无需重新登录）。
- **SC-207**：常规数据量下看板首屏 **2 秒内**出数；明细翻页每次 **1 秒内**返回。
- **SC-208**：100% 的赠送记录带非空理由；抽查 10 笔，理由都能独立说明为什么送。
- **SC-209**：超出上限的赠送 **100%** 被拦下（单次 > 12 个月、或赠送后 > 12 个月），
  且运营能看到「最多还能送多少」，不需要试错。

## Assumptions

- **早期机器绑定授权码不在本特性范围内**：商城侧没有它的数据（E10），看板只统计商城体系内的授权。
- **「授权」对个人以会员为单位计数**：同一会员的多段订阅算 **1 个授权**，不按行数累加。
- **「当年」按自然年**（1 月 1 日起），且以服务器时区为准。
- **看板只读 + 赠送**：本期不做批量赠送、不做导出、不做按销售/渠道归因。
- **赠送不产生订单、不产生收款**：它是运营行为而非交易行为；财务对账不依赖本特性的记录。
- **企业的「客户数」按企业主体计**，不按企业成员数计。
- **12 个月上限只约束「时长」**：赠送**席位**不设数量上限，受企业有效批次的容量约束（Q154 只提了时长）。
- **「剩余有效时长」按当前时刻计算**：已过期客户从今天起算；上限比对用「今天 + 12 个月」而非原到期日 + 12 个月。
- **赠送的版本由客户类型固定**：个人一律专业版、企业一律企业版；运营界面上**不出现**套餐/版本选择（Q158）。

## 明确不做（本期）

- 不做授权**续费提醒 / 到期邮件**（离线触达另行立项）。
- ~~不做赠送**撤销 / 撤回**~~ → **2026-11-19 起已做**（Q164 / FR-559~562）；
  仍不做**批量撤回**与**撤回后恢复**（撤回错了只能重新赠送，操作日志留痕）。
- 不做授权**转移**（个人转企业、企业之间转）。
- 不做**销售业绩 / 渠道来源**统计。
- 不改 C 端任何页面；不改桌面端取权益的方式。

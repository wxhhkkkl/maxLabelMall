## 一、前置条件

1. 测试库已按顺序执行 `sql/mysql/043-customer-service.sql`（5 张表 + 菜单/按钮权限）。
2. 后端以本地单体启动（`yudao-server`，48080），管理端与门面站分别启动。
3. 准备数据：
   - 会员 A：有手机号、已登录门面站；
   - 管理端账号：分别准备「只读」与「可处理」两种角色；
   - 回收地址：管理端先配置一份；
   - 支付：测试环境开启至少一个在线支付渠道；如需验证对公转账，打开 `trade_config.offline_pay_enabled`。
4. 用会员 A 登录门面站，进入「个人中心 → 客户服务」。

## 二、投诉咨询（US70 / US75）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 提交一条投诉（类型=投诉，内容必填，电话默认带出，附 1 张图） | 提交成功，列表出现记录，状态「待处理」 |
| 2 | 内容留空 / 电话留空 / 上传 6 张图 | 被拦下，提示具体字段，不产生记录 |
| 3 | 同一内容在 60 秒内连点两次 | 只生成一条记录 |
| 4 | 换另一个会员 B 登录 | B 看不到 A 的记录 |
| 5 | 管理端点开该投诉，填处理说明并标记已处理 | 状态变「已处理」，处理人/时间可追溯 |
| 6 | 会员 A 刷新个人中心 | 能看到「已处理」、处理说明与时间 |
| 7 | 管理端对同一投诉再次点处理 | 被拒（已处理），不覆盖原文 |
| 8 | 管理端「代建」投诉：按手机号搜索会员 A，填写内容提交 | 生成记录且来源=客服代建；A 登录后可见 |
| 9 | 未选择会员直接代建 | 被拦下，不产生记录 |

## 三、在线维修与开单（US71 / US72 / US75）

| # | 操作 | 期望 |
|---|---|---|
| 10 | 会员 A 提交维修申请（型号、故障、电话、返修收件地址，附图片） | 生成申请，状态「待联系」 |
| 11 | 型号或故障描述留空 | 被拦下并提示 |
| 12 | 一次申请填两台设备 | 表单不支持；必须分别提交两条申请 |
| 13 | 管理端记录电话联系结果（填写联系说明） | 状态变「已联系」，联系时间/说明可查 |
| 14 | 管理端开单：维修费 100 元 + 寄回运费 20 元 + 费用说明 | 生成维修订单，应付 120 元；申请状态「已开单」 |
| 15 | 会员 A 打开维修申请 | 能看到维修订单、费用明细、应付合计与支付状态 |
| 16 | 管理端对同一申请再次开单（或两个账号同时开单） | 只有一笔成功，另一笔被拒 |
| 17 | 开单时费用填负数 / 说明留空 | 被拦下，不产生订单 |
| 18 | 维修费与运费都填 0 | 订单显示「无需支付」，客户侧无支付按钮 |
| 19 | 管理端为会员 A 代建维修申请 | 生成成功，来源=客服代建，A 可见 |

## 四、维修支付与回收地址（US73 / US74）

| # | 操作 | 期望 |
|---|---|---|
| 20 | 会员 A 打开待支付维修单 | 显示维修费、寄回运费、合计、费用说明、回收地址与寄件说明；提示「支付后再寄件」 |
| 21 | 选择在线支付并完成支付 | 状态变「已支付」，记录支付时间/支付单号/渠道；刷新后可见 |
| 22 | 未支付时尝试标记「已寄出」 | 被拒；不出现寄出操作 |
| 23 | 已支付后填写快递公司与运单号，标记「已寄出」 | 状态「已寄出」，管理端可看到运单信息 |
| 24 | 管理端把状态推进到「维修中」「已完成」 | 客户侧依次可见，操作时间与说明可追溯 |
| 25 | 管理端修改回收地址 | 客户刷新后看到新地址 |
| 26 | 清空/未配置回收地址 | 客户侧显示「请联系客服获取邮寄地址」，不是空白 |
| 27 | 重复点击支付 / 模拟重复支付回调 | 只记一次支付，不重复改状态 |
| 28 | 客户尝试在「我的订单」找维修单 | 找不到（维修单只在客户服务） |
| 29 | 客户寻找自助退款入口 | 没有入口；只能联系客服 |
| 30 | 打开对公转账：选择后显示收款户名/账号/开户行/提示 | 状态「待确认收款」，客户不能凭此寄件 |
| 31 | 管理端确认收款（填流水号/付款人/到账时间） | 状态「已支付」，记录确认人与时间；客户可寄件 |
| 32 | 只读权限账号打开维修申请 | 看不到开单/改状态/确认收款按钮；直接调接口返回 403 |

## 五、明确不验证（本期不承诺）

- 物流轨迹查询、到货签收、维修完成后的寄回运单号（需求与规格已明确不做）。
- 短信 / 微信 / 站内通知（只做个人中心状态展示）。
- 维修订单开票、进入「我的订单」、客户自助退款。
- 批量处理、导出。
- 附件**单张 10MB** 的实际上限由上传接口配置决定：C 端上传组件按 10MB 拦截，
  服务端只保存 URL（URL 里没有大小信息）；若上传接口配置的上限更低，以接口为准。
- 小程序 / App 页面（服务端接口可供后续复用）。
- 性能压测；只按 SC-212 的「1 分钟内完成开单」做常规数据量观察。

## 六、上线顺序（执行前必须得到所有者确认）

> ⚠️ 宪法原则 VI：**任何时候不自动发版**。以下只是顺序说明，不等于授权。

1. 执行 `sql/mysql/043-customer-service.sql`（5 张表 + 菜单 + 两个权限点）
2. 发布后端（`yudao-server`）
3. 发布管理端（`yudao-ui-admin-vue3`）
4. 发布门面站（`storefront`）
5. 给客服角色勾选 `trade:customer-service:query` / `trade:customer-service:handle`
6. 配置回收邮寄地址（管理端「客户服务」）

**回滚**：

- 代码：回滚 jar、管理端静态资源与门面站静态资源（发版脚本自带备份）。
- 数据库：5 张表可保留（只增不改，留作审计）；菜单/权限可置为停用。
- 支付：维修支付单的 `merchantOrderId` 带 `repair:` 前缀，回滚后旧代码会把回调当作交易订单号解析失败
  —— **回滚前后端必须同时回滚，且停止新的维修支付**；已支付的维修单继续走后台人工处理。
- 已生成的维修订单与支付单**不会**因代码回滚而消失；需要人工与客户确认后续处理。

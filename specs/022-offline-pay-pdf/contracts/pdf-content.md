# 契约：对公转账单 PDF 内容

**版本**：2026-11-25 · 对应 FR-585~FR-598

本契约描述**下载到用户手中的 PDF 必须有/可有什么**。没有后端接口，
字段来源与格式化规则见 [data-model.md](../data-model.md)。

## 1. 触发与可见性

| 条件 | 行为 |
|---|---|
| `order.offlinePay` 非空（对公转账订单） | 订单详情页显示「导出对公转账单」入口 |
| `order.offlinePay` 为 `null`（非对公订单） | **不显示**入口，页面其余行为不变 |
| `offlinePay.waiting = true`（待收款） | 入口可见（US71，打款用） |
| `offlinePay.waiting = false`（已确认收款） | 入口**仍然可见**（US72，留档用） |
| `order.status = 40`（**已取消**） | **不显示**入口（Q168）；`waiting` 在取消后仍可能为 `true`，不能只看它 |

## 2. 文件

| 项 | 约定 |
|---|---|
| 格式 | PDF 1.3+，A4 纵向（210×297mm） |
| 文件名 | `对公转账单_<订单号>.pdf`；订单号中的 `\ / : * ? " < > \|` 被移除 |
| 生成位置 | 浏览器本地；不经过服务端 |
| 分页 | 内容超过一页时自动新增页；商品项与金额不得截断 |
| 文字 | 以图片渲染（Q165）；不要求可复制/搜索 |

## 3. 章节与顺序

PDF 自上而下必须包含（顺序固定）：

1. **标题区**：固定标题「宸发科技 · 对公转账单」
2. **收款账户**：收款户名 / 收款账号 / 开户行；`tip` 非空时显示提示语
3. **订单信息**：订单号 / 下单时间 / **订单状态**（待收款 / 已付款等） / 实付金额
4. **采购商品清单**：名称 / 规格 / 单价 / 数量 / 小计（逐项）
5. **金额明细**：商品小计 / 促销优惠 / 运费 / 优惠券抵扣 / 积分抵扣 / 会员优惠 / 应付总额
6. **收货信息**：收货人 / 手机号 / 收货地址
7. **开票信息**（条件渲染）：票种 / 抬头类型 / 抬头 / 税号 / 开票金额
8. **买家留言**（条件渲染）：原文
9. **页脚**：第 n / 共 m 页（可选，但有多页时 SHOULD 有）

## 4. 条件渲染

| 区块 | 渲染条件 |
|---|---|
| 转账提示语 | `offlinePay.tip` 去空格后非空 |
| 开票信息 | `order.invoice` 非空 **且** `status !== 20（已作废）` |
| 买家留言 | `userRemark` 去空格后非空 |
| 商品规格 | 订单项 `properties` 非空；为空时该行显示 `—` |

## 5. 文本安全

- 商品名、规格、留言、发票抬头/税号、收货地址等**用户可控文本**在写入 HTML 前
  必须转义 `& < > " '`。
- PDF 中必须显示原文（例如商品名 `A<B&C` 显示为 `A<B&C`），页面不得执行任何脚本。

## 6. 状态反馈

| 状态 | 行为 |
|---|---|
| 生成中 | 入口禁用，文案「生成中…」 |
| 成功 | 浏览器开始下载文件 |
| 失败 | 显示「生成 PDF 失败，请稍后重试」；不得下载空文件 |

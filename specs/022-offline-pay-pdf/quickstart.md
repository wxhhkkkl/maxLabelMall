# Quickstart：对公转账订单导出 PDF 凭证

**对应**：[spec.md](./spec.md) · [plan.md](./plan.md) · [contracts/pdf-content.md](./contracts/pdf-content.md)

## 1. 前置

- 门面站依赖已安装：`cd storefront && pnpm install`（新增 `jspdf` / `html2canvas`）
- 本地后端可访问 `/app-api`（与既有门面站开发方式相同）
- 准备一笔**对公转账**订单（结算页选「对公转账」下单，状态「待收款」）

## 2. 自动验证

```bash
cd storefront
pnpm test                 # Vitest 全量
pnpm ts:check             # 类型检查
```

必须全绿，重点用例：

| 用例 | 验证 |
|---|---|
| `offlinePayPdf.spec.ts` 内容模型 | 字段映射、订单状态（待收款 / 已付款）、空值 `—`、金额/时间格式、`小计 = 单价 × 数量` |
| `offlinePayPdf.spec.ts` 转义 | 商品名/留言含 `<>&"'` 时 PDF HTML 为转义文本 |
| `offlinePayPdf.spec.ts` 文件名 | `对公转账单_NO-xxx.pdf`，非法字符被移除 |
| `offlinePayPdf.spec.ts` 分页 | 打桩画布超高时 `addPage` 次数正确 |
| `OrderDetailView.spec.ts` | 非对公单无入口；待收款/已收款对公单均有入口；**已取消**对公单无入口；导出失败时提示不崩溃 |

## 3. 手工验收（SC-217~SC-221）

| # | 操作 | 期望 |
|---|---|---|
| 3.1 | 打开一笔「待收款」对公订单 | 页面出现「导出对公转账单」 |
| 3.2 | 点击导出 | 直接下载 `对公转账单_<订单号>.pdf`；生成期间按钮显示「生成中…」 |
| 3.3 | 打开 PDF | 含户名/账号/开户行、订单号、下单时间、**订单状态**、实付金额、商品清单；与订单页逐项一致（SC-218） |
| 3.4 | 核对商品行 | 每项名称/规格/单价/数量/小计齐全；`小计 = 单价 × 数量` |
| 3.5 | 核对金额明细 | 商品小计、促销优惠、运费、优惠券、积分（0）、会员优惠、应付总额齐全 |
| 3.6 | 核对附加内容 | 收货信息、开票信息（有申请时）、买家留言（非空时）均出现 |
| 3.7 | 打开一笔**非对公**订单 | **没有**导出入口（SC-219） |
| 3.8 | 对已确认收款的对公订单重复 3.1~3.3 | 入口仍在、内容不缺少账户（US72） |
| 3.9 | 用 20 个以上商品的订单导出 | 所有商品与金额都在，跨页不截断（SC-220） |
| 3.10 | 商品名/留言含 `<script>alert(1)</script>` | PDF 显示原文；页面无弹窗（SC-221） |
| 3.11 | 收款账户未配置时导出 | 对应位置显示 `—`，不编造（008 口径） |
| 3.12 | 打开一笔**已取消**的对公订单 | **没有**导出入口（SC-222 / Q168） |
| 3.13 | 20 项商品订单点击导出并计时 | 开始下载 **≤ 3 秒**（SC-223，普通桌面浏览器） |

## 4. 显式不验证

| 项 | 原因 |
|---|---|
| 物理打印机色彩/边距 | 无打印机基线，只验证文件可打开与内容完整 |
| 无头浏览器自动下载 e2e | 下载事件在 Playwright 无头环境不稳定；由上面手工步骤覆盖 |
| PDF 文字可复制/搜索 | Q165 已接受图片化渲染 |
| 主流浏览器之外的兼容性 | 只覆盖 Chrome / Edge / Safari / Firefox 当前版本 |

## 5. 回滚

- 纯前端特性，回滚 = 回退 `storefront` 的本次改动并重新发布门面站；
  无数据库脚本、无后端改动，无需数据回滚。

# Quickstart：代客开票

**对应**：[spec.md](./spec.md) · [plan.md](./plan.md) · [contracts/admin-api.md](./contracts/admin-api.md)

## 1. 前置

- 后端可从 IDE / jar 启动（与既有开发方式一致）
- 管理端依赖已安装（`yudao-ui-admin-vue3`：`pnpm install`）
- 准备：一个普通客户、一笔可下单商品；一笔已支付订单；一笔含企业授权商品的订单（用于企业抬头）

## 2. 自动验证

```bash
# 后端（模块内）
mvn -pl yudao-module-mall/yudao-module-trade-server -am test \
  -Dtest=AgentOrderServiceTest,TradeOrderInvoiceServiceImplTest \
  -Dsurefire.failIfNoSpecifiedTests=false

# 管理端
cd yudao-cloud/yudao-ui/yudao-ui-admin-vue3
npx vitest run src/views/mall/trade/order/agent \
  src/views/mall/trade/order/detail/index.spec.ts \
  src/views/mall/trade/invoice
```

重点用例见 tasks.md 的测试任务；全绿后才进入手工验收。

## 3. 手工验收（SC-224~SC-229）

| # | 操作 | 期望 |
|---|---|---|
| 3.1 | 管理端 → 代客下单，选客户/商品，打开「开具发票」开关 | 出现完整发票字段（票种/抬头类型/抬头/税号/地址/电话/开户行/账号/行号/邮箱） |
| 3.2 | 填企业普票（名称+税号），提交 | 订单创建成功；详情「发票详情」显示「待开票」，字段与填写一致（SC-224） |
| 3.3 | 提交一个**缺税号**的企业普票 | 提交失败，**订单列表不新增订单**（SC-225） |
| 3.4 | 企业抬头下选择「电子增值税专用发票」失败；选「个人」后再选专票应被禁用 | 无法形成「个人+专票」组合 |
| 3.5 | 用含**企业授权商品**的订单在下单时选「个人」抬头 | 被拒并提示必须企业抬头（SC-226） |
| 3.6 | 结算后实付为 0 的订单 | 「开具发票」开关禁用，提示不能开票 |
| 3.7 | 对一笔已支付、未取消、实付>0、无发票的**普通订单**，详情点「代申请发票」 | 弹窗可填完整字段并提交成功；客户 C 端详情显示「待开票」（SC-227） |
| 3.8 | 对未支付 / 已取消 / 实付 0 / 已有发票的订单 | 不显示「代申请发票」入口；直接调接口被拒（SC-227） |
| 3.9 | 客户已在 C 端申请后再补申请 | 报「该订单已申请发票」，仍只有 1 条记录（SC-228） |
| 3.10 | 企业授权订单补申请选「个人」抬头 | 被拒，提示企业抬头 |
| 3.11 | 查看该订单的操作日志 | 出现「后台代客户申请发票」，可追溯到操作人（SC-229） |
| 3.12 | 确认收款前尝试给对公待收款单开票（管理端发票页） | 被拒（订单未支付），与既有 006 一致 |
| 3.13 | 不勾选开票直接下单 | 不产生发票申请（行为与改动前一致） |

## 4. 显式不验证

| 项 | 原因 |
|---|---|
| 发票文件上传/下载全链路 | 006 既有能力，本特性不改，只验证「待开票」状态可达 |
| 并发下同一订单两次补申请 | 由 `uk_order_id` 兜底；不以压测形式验证，只做一次重复提交验证 |
| 权限矩阵（自定义角色） | 复用既有 `trade:order:update`，不新增权限点；仅验证超管/无权限两种 |

## 5. 上线与回滚

- **上线顺序**：先发**后端**，再发**管理端**；无 SQL、无新权限数据。
- **回滚**：回退后端与管理端本次改动即可；已创建的发票申请属于 006 既有数据，不需要清理。
- 未取得所有者确认前不得发版（宪法原则 VI）。
